# provisioning/setup.ts — A foreign cached engine image is reused without a check

- Added: 2026-10-06
- Applies to: orchestration.md step 2a/3 (provisioning), provisioning/setup.ts "Check database image"
- Evidence: On row 30 `setup.ts --database pdpgsql` failed after 64 s with "timed out waiting for PostgreSQL initialization"; the container exited 255 with empty logs. The cached `pmm-qa/pdpgsql:17` (built 7 h earlier by another branch) had `ENTRYPOINT /lib/systemd/systemd`, which provisioning/images/engines/pdpgsql/Dockerfile never sets. setup.ts skips the build whenever the tag exists. Retagging it and `node images/build.ts pdpgsql=17` fixed it in 1 run.
- Proposed change: On an engine container that exits within seconds with no logs, check `docker image inspect <tag> --format '{{.Config.Entrypoint}}'` against the Dockerfile before retrying; retag the foreign image (never delete it) and rebuild through images/build.ts.
