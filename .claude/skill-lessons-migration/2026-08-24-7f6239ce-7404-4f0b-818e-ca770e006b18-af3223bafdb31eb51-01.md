# .claude/skills/codeceptjs-migration/run.md — A withdrawn advisory needs no re-derivation at the next gate

- Added: 2026-08-24
- Evidence: The Gate ledger's scoping rule is written for blockers: an entry that is not a pass with `status: open` blockers scopes the next pass. It says nothing about advisories, so the parent's final-gate brief asked for four already-`withdrawn` advisories to be re-confirmed, and re-confirming one of them required repeating the same live MCP identity check the initial gate had already run. The cost was low only because it batched into a page sweep that was happening anyway. The re-derivation produced no new information about any of the four.
- Proposed change: In `run.md` section Gate ledger, extend the scoping rule to advisories: an advisory recorded `withdrawn` needs no re-derivation at a later gate unless the subject changed the code it was about. Only `open` items and the delta since the last entry are in scope.
