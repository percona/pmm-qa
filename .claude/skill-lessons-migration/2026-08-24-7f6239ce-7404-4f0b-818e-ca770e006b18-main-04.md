# .claude/skills/codeceptjs-migration/branch-workflow.md — Enumerate the source's consumers beyond .github/workflows before retiring it

- Added: 2026-08-24
- Evidence: The row-4 coverage analysis was performed entirely against tag expressions in `.github/workflows/`. The writer, the runner, and both gates all concluded that `@grafana-pr` "has no consumer in any workflow" - literally true, and it caused the tag to be treated as decorative. A user challenge surfaced a consumer the scan could not see: `codeceptjs-e2e/package.json` defines `e2e:grafana-pr`, which runs `codeceptjs run -c pr.codecept.js --grep '@grafana-pr'`, and 5 of the source's 7 active scenarios carry that tag. Nothing inside pmm-qa invokes it, so the caller is external - the script name indicates percona/grafana CI running PMM's suite against a Grafana PR. The catch-all `e2e` script matches the source too, excluding only `@not-ui-pipeline` and `@not-pr-pipeline`. If that external caller exists, retiring the source drops coverage the migration's new Playwright job cannot restore, because that script invokes CodeceptJS only.
- Proposed change: In `branch-workflow.md` section Workflow coverage, require the consumer enumeration to cover `codeceptjs-e2e/package.json` scripts and any caller outside `.github/workflows/` in addition to workflow tag expressions, and to state for each migrated tag either its consumers or that a cross-repository caller could not be ruled out. A tag with no workflow consumer must not be reported as having no consumer.
