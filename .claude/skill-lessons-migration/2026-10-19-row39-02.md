# .claude/skills/codeceptjs-migration/orchestration.md — a second pmm-server container hijacks pmm-framework registration

- Added: 2026-10-19
- Applies to: orchestration.md step 3, adding databases to a running environment while a second PMM server container exists (renderer-less or self-provisioned server)
- Evidence: Row 39 started `pmm-server-norender` (:4443) to measure PMM-T1070. The next `local-pmm.sh up --database haproxy --database ps,SETUP_TYPE=replication` registered both with `pmm-server-norender`: `lib/pmm_server.sh:21` takes `candidates[0]` and only warns. `--pmm-server-ip pmm-server` then failed (dials port 443, server listens 8443). Fix that worked: remove the misregistered containers, `docker stop pmm-server-norender`, re-run `up`, `docker start` it again.
- Proposed change: In step 3, say: stop every extra pmm-server container before `local-pmm.sh up` adds databases, and confirm `pmm-admin status` URL is `https://pmm-server:8443/` in a new container afterwards.
