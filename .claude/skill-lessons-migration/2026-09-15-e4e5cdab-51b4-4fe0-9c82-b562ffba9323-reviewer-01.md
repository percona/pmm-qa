# .claude/skills/codeceptjs-migration/run.md - a gate stores its evidence verbatim, because the next spawn is a fresh instance with no transcript

- Added: 2026-09-15
- Applies to: `.claude/skills/codeceptjs-migration/run.md` ("Gate ledger")
- Evidence: Row 10's final gate was re-spawned for a message-only amend, and the parent asked it to carry attempt 1's `conventionScriptOutput` and `shape` block forward by copying them. It could not: each gate spawn is a fresh instance holding no prior transcript, and the ledger preserves conclusions rather than evidence - entry A4 records "5 advisories on lines 73, 92, 123, 131, 155", not the five advisory lines. The attempt only completed because `check-migration-conventions.sh` is deterministic over an unchanged tree, so re-running it reproduced the bytes rather than approximating them. An MCP locator pass or a Playwright execution log would not have been recoverable at all, and the gate would have had to decline the request outright.
- Proposed change: Extend the ledger schema so a passing entry stores the evidence itself - the full convention script output and the populated `shape` block - not a summary of it. Note in the same section that a re-spawned gate cannot copy anything from an earlier attempt except through the ledger, so anything the parent may later need to re-read has to be in there verbatim.
