# .claude/skills/codeceptjs-migration/branch-workflow.md - a counting command that silently under-matches returns a plausible number, not an error

- Added: 2026-09-15
- Applies to: `.claude/skills/codeceptjs-migration/branch-workflow.md` ("When retiring a CodeceptJS source, check every job whose grep matches its title tags")
- Evidence: Two independent under-counts on row 10, both returning believable figures with exit 0. `git grep <rev> -- 'codeceptjs-e2e/tests/**/*_test.js'` reported 7 files where the answer was 13, because git's default pathspec magic is not `:(glob)` and `**` does not span directories there; a directory pathspec filtered with `| grep '_test\.js$'` is both shorter and correct. Separately, parsing Playwright's `--list` output for `Total: N tests` missed the singular `Total: 1 test`, silently reporting 0 for `@pmm-psmdb-integration`, `@LBAC` and `@user-password`. The section already warns that an under-count deletes a job that still tests something; these are the two mechanisms that produce one without any signal that counting failed.
- Proposed change: Name both forms in that section as known-bad, with the working replacements, and add the cross-check that catches this class generally: any tag or file count is measured twice by different mechanisms (a `grep -o`/`grep -l` pair, or a count plus an explicit listing whose length is checked) and the two are stated together. A single number with no second opinion is not a measurement.
