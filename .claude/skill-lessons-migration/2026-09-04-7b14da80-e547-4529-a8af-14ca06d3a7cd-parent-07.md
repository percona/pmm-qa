# .claude/skills/codeceptjs-migration/SKILL.md — port the element, not the selector; a resolving locator is not a well-formed one

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/SKILL.md` ("Native Playwright rules"), `run.md` (step 2 item 7), `audit-checklist.md`
- Evidence: Row 5 ported `fields.settingsTitle = '[class*="title-info-container"]'` from the CodeceptJS POM verbatim. It matches Grafana's emotion-hashed `css-bk8b94-title-info-container`, which changes on a Grafana bump. Both gates verified it — attempt 1 MCP-verified it resolved, attempt 2 re-verified count 1 and visible — and the migrated test passed. A review bot on the PR then flagged it, and `getByRole('heading', { exact: true, name: 'Settings' })` replaced it after the PR was already open. The gap: everyone asked "does this locator resolve to the element the source intended?" and nobody asked "is this the form `playwright-practices.md` mandates for that element?". `SKILL.md` currently says "When unsure, keep the source syntax", which reads as authorising a verbatim selector port; `playwright-practices.md`'s ladder ranks a framework-hashed class last.
- Proposed change: State that a ported locator is migrated at the level of the *element*, not the *selector string*. Once the live DOM is available, re-derive each ported locator at the highest ladder rung that resolves to the same element, and keep the source selector only when no higher rung does. Add a matching checklist line: for each ported locator, record the ladder rung chosen and, if it is CSS-by-class, why nothing higher resolved. Note explicitly that "the source used it and it is green today" is evidence the element is right, never that the selector form is right — CodeceptJS sources predate the ladder entirely.
