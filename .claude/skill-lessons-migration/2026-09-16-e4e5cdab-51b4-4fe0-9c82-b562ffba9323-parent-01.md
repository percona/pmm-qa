# .claude/skills/codeceptjs-migration/locator-fix.md - a locator count is only valid over what Grafana has rendered

- Added: 2026-09-16
- Applies to: `.claude/skills/codeceptjs-migration/locator-fix.md`, and the MCP locator pass in `run.md` section 4
- Evidence: Row 10's PMM Health locators were verified by counting matches per panel title: 1 each, in two independent gate passes, and the test passed Playwright strict mode four times. A review bot said four of the seven titles are duplicated in the dashboard JSON; it was refuted twice on the strength of those counts and withdrew the finding, recording the refutation as a learning and repeating it to a human reviewer. Both refutations were wrong. Measured afterwards on a live server: `graph/d/pmm-health` holds 89 grid items and ZERO collapsed rows; a default load renders only 19 `section[data-testid]` panels; after `dashboard.loadAllPanels()` scrolls every grid item into view, 81 render and `ManageD Status`, `QAN API Status`, `Grafana Status` and `Clickhouse Status` each resolve to 2. Grafana lazy-renders below the fold, so the count of 1 measured the viewport, not the dashboard, and the green strict-mode runs proved uniqueness only among rendered elements - the exact guarantee that lapses when a taller viewport, a faster machine or a Grafana bump renders one more panel.
- Proposed change: In `locator-fix.md`, require every count-based uniqueness check on a dashboard to run after `loadAllPanels()` or an equivalent full scroll, and to state both numbers - panel sections rendered, and matches per locator - so a count taken over a partial DOM is visible as one. Add that a passing strict-mode run is not evidence of uniqueness on a lazy-rendering page. Where a title genuinely repeats, pin the panel with `[data-griditem-key="grid-item-<panelId>"]` scoped to the title, so an id drift fails loudly; `.first()` is positional and fails silently. Note the second-order cost: a confident refutation built on a partial-DOM count was ingested by the reviewing bot as a durable false learning and relayed to a human, so the correction had to be issued publicly on two threads.
