# .claude/skills/codeceptjs-migration/branch-workflow.md — verify a widened grep by set difference, and list the added alternative on its own

- Added: 2026-09-09
- Applies to: `.claude/skills/codeceptjs-migration/branch-workflow.md` ("Check selectability per scenario and across every consumer")
- Evidence: Row 7 widened `settings_playwright` from `@settings` to `@settings|@grafana-pr`, and the handoff's before/after totals (12 -> 13) were correct. Listing the added alternative on its own showed `@grafana-pr` already selecting 7 Playwright tests; the union grew by 1 only because 6 of them were row 4's `settingsPageElements.test.ts`, which already carries `@settings`. Two totals cannot separate "adds one test" from "adds one test plus N pre-existing overlaps", and had the overlap been zero the same two totals would have read 12 -> 19 with no indication of which 7 files the server-only job had newly acquired. `comm -13` over two sorted `--list` outputs named the added set exactly (one test) and proved the removed set empty, in one command.
- Proposed change: In that section, tell the runner to capture each `--list --grep` selection to a sorted file and report the added and removed sets from `comm`, not the two totals, and to list any newly added alternative on its own as well as in the union — the alternative's own count is what says how much the edit could have pulled in, and a small union delta is a claim about overlap that only the set difference substantiates.
