# .claude/skills/codeceptjs-migration/SKILL.md - refute a bot's locator finding with the rendered DOM and the strict-mode run, not with prose

- Added: 2026-09-15
- Applies to: `.claude/skills/codeceptjs-migration/SKILL.md` ("Review comments"), and `locator-fix.md`
- Evidence: On PR #1437 a review bot raised a Major "duplicate panel titles" finding against `panelByExactName`, naming four panels and predicting a strict-mode failure before the first assertion ran. It was reasoning from the dashboard JSON, where those titles do appear twice. The refutation was three facts already in hand and none of them an opinion: the live dashboard renders 17 `section[data-testid]` panels with each asserted title at count 1, measured through MCP in two independent gate passes; the source's own `contains()` XPath resolves to 1 for the same seven; and the test had already passed twice under Playwright strict mode, which would have thrown `resolved to N elements` on the very first panel the bot named. Offering the likely cause of the discrepancy - duplicates sitting in collapsed rows, which never render and so never enter the match set - turned a standoff into a withdrawal: the bot retracted the finding and recorded the collapsed-row distinction as a learning.
- Proposed change: In "Review comments", say that a bot finding predicting a locator or strict-mode failure is answered with the rendered-DOM count and the green run that would have failed if it were right, and that naming the mechanism behind the bot's evidence (dashboard JSON counts panels a rendered page does not) is what closes the thread rather than leaving it contested. A green strict-mode run is a stronger statement about multiplicity than any argument about the source of truth, because strict mode fails on exactly the condition being alleged.
