# .claude/skills/codeceptjs-migration/orchestration.md — Provision only from WSL, and confirm WSL can reach Docker first

- Added: 2026-10-09
- Applies to: orchestration.md steps 2a and 3 (`local-pmm.sh up` on Windows)
- Evidence: In row 32, Docker Desktop was stopped at the start. After it started, WSL Ubuntu still had no `docker` (an empty `/mnt/wsl/docker-desktop/cli-tools`), and `wsl --terminate Ubuntu` did not bring it back. Three provisioning attempts from Git Bash failed:
  - Plain: `docker exec` paths were rewritten to `C:/Program Files/Git/usr/...`, and pmm-agent wrote an empty config.
  - `MSYS_NO_PATHCONV=1`: the compose `-f` path broke.
  - Selective `MSYS2_ARG_CONV_EXCL`: the run hung.
  The half-provisioned container then reported "OK" with no pmm-agent running. WSL Docker came back minutes later, and attempt 4 from WSL took 17 s.
- Proposed change: Before step 2a, run `wsl -d Ubuntu -- docker version --format '{{.Server.Version}}'`. If it fails, wait and retry; never fall back to Git Bash for `local-pmm.sh` or pmm-framework. Run `down` from WSL before every retry, so a half-provisioned container from a failed attempt is never reused.
