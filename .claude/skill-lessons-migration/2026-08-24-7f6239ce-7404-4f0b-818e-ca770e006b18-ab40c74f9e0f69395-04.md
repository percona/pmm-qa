# .claude/skills/codeceptjs-migration/run.md — A beforeEach-restoring file is rerunnable even when its last scenario leaves state dirty

- Added: 2026-08-24
- Evidence: `run.md` step 5 warns that a test selecting state by index is not rerunnable on a reused environment without a reset first, and that a refused reset must be escalated to the parent. Row 4's last scenario mutates data retention and the public address, and its `afterEach` clears only the address - so the environment is left dirty and the warning appears to apply. It does not: the reset runs in `beforeEach`, at the head of every test including that one, so the file is self-preconditioning and reran green with no manual reset and no classifier refusal. The final gate confirmed the residue live and confirmed the reasoning.
- Proposed change: In `run.md` step 5, distinguish the two cases: the rerun hazard is state a test *reads* without establishing, not state a test *leaves*. A file whose `beforeEach` restores its own precondition needs no external reset regardless of what its last scenario leaves behind - check where the reset runs before escalating one.
