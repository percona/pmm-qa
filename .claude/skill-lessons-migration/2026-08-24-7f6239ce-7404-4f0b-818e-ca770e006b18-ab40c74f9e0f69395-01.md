# .claude/skills/codeceptjs-migration/branch-workflow.md — The append-to-nightly coverage default assumes the retiring source has nightly coverage to preserve

- Added: 2026-08-24
- Evidence: Two independent agents reached the same conclusion on row 4. The source carries `@settings` and `@grafana-pr`; the nightly CodeceptJS greps match neither, and the FB suite's `@fb-settings` is a different literal - so the source's only CI consumer is a PR-triggered job in `e2e-tests-matrix.yml`. The initial gate recommended the documented default of appending the tag to the nightly `test_execution_playwright` entry. The runner rejected it and the final gate upheld the rejection: appending would have manufactured new nightly coverage that never existed while leaving the surface the source actually runs on with zero Playwright coverage once the tag retires - exactly the "coverage vanishes on retirement" failure the rule exists to prevent. The default is stated unconditionally, which is what made a correct-by-the-book recommendation wrong.
- Proposed change: In `branch-workflow.md` section Workflow coverage, precede the append-to-nightly default with its precondition: first determine which jobs select the *source* today, across both nightly and PR matrices, then add Playwright coverage on those same surfaces; append to the nightly entry only when the source is actually in a nightly grep.
