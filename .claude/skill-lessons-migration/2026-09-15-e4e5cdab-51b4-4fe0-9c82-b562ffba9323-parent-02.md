# .claude/skills/codeceptjs-migration/run.md - re-measure every number in a commit body before the final gate, not after it passes

- Added: 2026-09-15
- Applies to: `.claude/skills/codeceptjs-migration/run.md` (section 5b) and `branch-workflow.md` ("Move the work across")
- Evidence: Row 10's retirement commit body carried three inaccuracies, all found after `FINAL_REVIEW_PASS`: `@gssapi-nightly` scenario counts stated as 28 -> 27 when the tag greps 29 -> 28; a cross-check parenthetical in the `@nightly` bullet reading "(12 and 11 respectively)" while that bullet's own preceding sentence said 13 and 12, because the `@gssapi-nightly` file counts had been pasted into it; and `nightly-e2e-tests-matrix.yml` described as `workflow_dispatch`-only when it also declares `workflow_call`. Each fix was a message-only amend that moved HEAD and therefore invalidated the passing gate, so one row spent three final-gate attempts on prose about counts while the tree never changed once. This repository squash-merges commit messages into `main`, so each would have landed verbatim. The body is long precisely because it documents a real coverage loss honestly - length is what made it worth checking, not a reason to skip it.
- Proposed change: Add a step at the end of 5b, before the runner returns: re-measure every number, filename, trigger and line reference in each commit body against the tree, and state the command used for each. Note that a claim's arithmetic being right does not make the claim right - two of the three errors here were correct numbers about the wrong tag. Cheap before the gate, three gate spawns after it.
