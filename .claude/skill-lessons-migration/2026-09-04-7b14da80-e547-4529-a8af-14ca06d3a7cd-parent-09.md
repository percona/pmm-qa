# .claude/skills/codeceptjs-migration/playwright-practices.md — "meaningful phases" is too vague to stop a step wrapping one bare assertion

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/playwright-practices.md` ("Structure")
- Evidence: The rule reads "Wrap meaningful phases in `await pmmTest.step('<sentence>', async () => { ... })`, including value-returning steps." On row 5 the writer wrapped a single bare `expect` in a step, both gates passed it, and a review bot on the PR asked for it to be unwrapped: `expect` is already a reported step, so the report carried two nested entries for one assertion. Counting the repo settles it — across `e2e_tests/tests` there are 168 `pmmTest.step` calls, 31 contain exactly one `expect`, and only 4 of those contain no accompanying action. The dominant shape is action-plus-assertion, and a lone assertion is a 2% outlier.
- Proposed change: Replace "meaningful phases" with a testable threshold: a step groups two or more actions or assertions, or one action together with the assertion that checks it. A step around a single bare `expect` is not a phase — `expect` reports itself, and the wrapper only adds a duplicate nested entry. Cite the 4-of-168 count so the next writer does not have to re-derive it, and note that `playwright/expect-expect` is unaffected either way, so lint will not catch this.
