# .claude/skills/codeceptjs-migration/run.md — Playwright jobs key on pmm_test_flag, not tags_for_tests

- Added: 2026-08-24
- Evidence: `run.md` step 8 tells the writer to check migrated scenario titles against "the grep expressions the destination jobs already carry", and the only input name it names is the CodeceptJS one. The Playwright runner workflow takes its expression as `pmm_test_flag`. A parse that looks for `tags_for_tests` finds zero Playwright jobs and returns a clean, empty result - indistinguishable from "no job greps this tag", which happens to have been the true answer for row 4 and would therefore not have been caught by the outcome.
- Proposed change: In `run.md` step 8, name both input keys explicitly - `tags_for_tests` for CodeceptJS jobs and `pmm_test_flag` for Playwright jobs - and require the scan to report how many jobs of each kind it found, so a zero-match parse is distinguishable from a zero-coverage answer.
