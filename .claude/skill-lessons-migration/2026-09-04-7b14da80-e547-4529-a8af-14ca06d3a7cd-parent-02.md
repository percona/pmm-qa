# .claude/skills/codeceptjs-migration/run.md — the destination job's `setup_services` is a free cross-check on the derived environment bucket

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/run.md` (step 2 item 6 and step 8) and `.claude/skills/codeceptjs-migration/orchestration.md` (step 2a)
- Evidence: Row 5's tracker planned `B2` / `--database pgsql`. The source only authorizes and reads Grafana's own `graph/admin/settings`, so the real bucket is `B1` / none. The destination Playwright job `settings_playwright` in `.github/workflows/e2e-tests-matrix.yml` runs `setup_services: -h` (server-only), which corroborates B1 without reading the source at all. The wrong tracker value came from the CodeceptJS `settings_and_cli` job, which runs `--database pgsql` because it provisions for the whole `@settings|@cli` union rather than for this one test. So the retiring source job's setup is a false signal and the destination job's is a true one.
- Proposed change: In step 8, after identifying each scenario's destination job, state that job's `setup_services` and compare it against the derived `setupServices`. It costs nothing, because step 8 already opens those workflow files, and it catches a wrong bucket before provisioning rather than after. Add the caution that the retiring CodeceptJS job's `setup_services` is NOT a valid cross-check: a union grep provisions for every tag in the union, so it over-states what any single migrated scenario needs.
