# .claude/skills/codeceptjs-migration/branch-workflow.md — the "does retirement empty this CodeceptJS job" count is a grep-selection count, not a file scenario count

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/branch-workflow.md` ("Workflow coverage")
- Evidence: Three agents miscounted the same table on row 5, each in a different direction. The runner's first matcher used a bare `Scenario(` and returned 6 scenarios in 2 files, silently dropping all three `Scenario.skip(` rows in `sttSettings_test.js`. The final reviewer hit the same form and noted it would have produced a false `FINAL_REVIEW_FAILED` against an accurate commit message. The publishing runner then counted every scenario in the three files and got 22 (3/14/5), because it counted files rather than grep matches. The correct figure for `@settings|@cli` after retirement is 11 tagged scenarios across 3 files (7+3+1), of which 6 are active.
- Proposed change: State explicitly that this is a count of scenarios whose *title* carries one of the job's grep tags, not of scenarios in the file, and that the matcher must catch `Scenario.skip(`, `xScenario(` and `Data(...).Scenario(` as well as `Scenario(`. Say which quantity licenses which decision: the tagged count reproduces what CI selects, the active count decides whether the job may stay in place. An under-count produces a false "this job is now empty, delete it"; an over-count hides a genuinely vacuous job, which then reports green forever while testing nothing.
