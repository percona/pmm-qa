# .claude/skills/codeceptjs-migration/SKILL.md — a synchronization guard is not coverage, and collapsing two waits changes the timeout budget

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/SKILL.md` ("Migration invariants" and "Drop what is inert in Playwright")
- Evidence: Two halves of the same PR review comment on row 5, and the gates got one right and one wrong.
  Wrong: the re-gate rejected swapping the load guard to `getByRole('heading', ...)` as "a fidelity change for style, not a defect fix", because it targets the `h1` rather than the wrapper `div` the source asserted. But the "Preserve exactly" list covers scenarios, titles, tags, hooks, data rows, assertions and assertion strictness — it does not cover which node a synchronization wait watches. Treating a load gate as coverage let a brittle emotion-hashed class survive both gates.
  Right: the same comment also asked to drop the guard entirely and give the remaining assertion `ONE_MINUTE`. The source waited 60s on the title and a further 30s on the type cell, so one 60s budget cuts the worst case from 90s to 60s. That is a behaviour change, and the writer and both gates correctly refused it — but each derived the arithmetic from scratch, because it is written down nowhere.
- Proposed change: In "Migration invariants", say the list is exhaustive for fidelity purposes, and that a synchronization wait is a means, not a preserved behaviour — its locator is governed by the ladder in `playwright-practices.md` like any other, so re-anchoring one is not a retitle-class change and needs no reviewer dispensation. Separately, in "Drop what is inert", add the budget rule: sequential source waits on *different* locators sum, so collapsing them into one assertion timeout is outcome-neutral only if that timeout is at least the sum. State the sum explicitly when collapsing.
