# .claude/skills/codeceptjs-migration/branch-workflow.md — "nightly" names two different workflows; say which one

- Added: 2026-08-24
- Evidence: Correcting an earlier statement made in this session. The row-4 coverage decision was justified as "the source's only CI consumer is a PR-triggered job", which is wrong: `e2e-tests-matrix.yml` carries `schedule: cron '0 2 * * *'` and its `settings_and_cli` job has no job-level `if:` gate, so the source does run on a nightly schedule. What is true is narrower - the source is absent from `nightly-e2e-tests-matrix.yml`, a `workflow_dispatch`-only matrix fired by Jenkins against an externally-managed PMM Server, whose three greps are `@qan|@valkey-nightly|@permissions-nightly|@pt-summary-nightly|@pbm-nightly`, `@nightly`, and `@menu|@annotations`; the source's tags `@settings` and `@grafana-pr` match none. The wording came from a subagent handoff and was repeated up the chain without checking the trigger block. The decision it justified is still correct, and is better justified once stated precisely: the new job sits in `e2e-tests-matrix.yml` and therefore inherits both the PR trigger and the 02:00 cron, reproducing exactly the surfaces the source had.
- Proposed change: In `branch-workflow.md` section Workflow coverage, require every coverage claim to name the workflow file rather than the word "nightly", and to state each candidate job's trigger block (`pull_request`, `schedule`, `workflow_dispatch`) as read, since both matrices run on a nightly cadence by different mechanisms.
