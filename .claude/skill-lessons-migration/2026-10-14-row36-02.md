# .claude/skills/codeceptjs-migration/orchestration.md — provision the appended target file's databases before the runner

- Added: 2026-10-14
- Applies to: orchestration.md step 2a/3 when the writer appends to an existing target file
- Evidence: Row 36 provisioned the source's databases only (ps single slowlog, pdpgsql, psmdb pss). The writer appended to `storedMetrics/details.test.ts`; the runner's whole-file run then failed 3 pre-existing tests (PMM-T149/T223 need pxc, PMM-T2014 needs `ps,SETUP_TYPE=gr,QUERY_SOURCE=slowlog`), costing a ~15 min runner loop and a mid-run `local-pmm.sh up` addition (pmm-framework picks free host ports, so a second PS topology joins a running env cleanly).
- Proposed change: Once the writer names an existing target file, the parent derives that file's databases (`migration.sh setup` over its titles, or the services it filters on) and adds them to the running environment with `local-pmm.sh up --database ...` before spawning the runner; the tracker Setup and the CI dispatch carry the union.
