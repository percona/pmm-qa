# .claude/skills/codeceptjs-migration/branch-workflow.md — Resolve a control merge conflict hunk by hunk, never with --theirs

- Added: 2026-10-08
- Applies to: branch-workflow.md Control branch preflight, orchestration.md step 1 (merge origin/main)
- Evidence: Row 32's `git merge origin/main` stopped with conflicts in `.gitignore` and three pmm-framework Dockerfiles. `git checkout --theirs -- .gitignore` replaced the whole file with main's copy, so it also dropped control's auto-merged `.claude/*` exceptions (`!.claude/skills/`, `!.claude/skill-lessons-migration/`, ...). The next `git add` of the tracker failed with "paths are ignored". It was caught only because of that, and the unpushed merge had to be amended. The Dockerfiles were safe only because control had no hunks of its own there (`git diff HEAD~1 HEAD` showed only main's lines).
- Proposed change: In Control branch preflight, add: resolve each conflict on its markers (`git merge-file -p ours base theirs` for an add/add or a file you rebuild). Use `--theirs`/`--ours` only after `git diff <side>~ <merged>` shows the other side has no hunks in that file. Before committing the merge, `git check-ignore -v .claude/skills/codeceptjs-migration/tracker.md` must exit 1.
