# .claude/skills/codeceptjs-migration/SKILL.md — QAN Explain clicks pollute a slowlog source's row 1

- Added: 2026-10-14
- Applies to: any QAN migration that searches a PS/MySQL slowlog service and selects row 1 before clicking Explain
- Evidence: Row 36 initial gate B1: each Explain click logs `explain ...` and `explain format=json ...` fingerprints that match the same search and outrank the workload query, so PMM-T13 PS passed on a fresh server and failed every rerun (runner step 5, CI retries, shared nightly server). Fixed with a `firstWorkloadRow` builder filtering `hasNot: getByRole('cell', { name: /^explain\b/i })`; two back-to-back runs then 5/5.
- Proposed change: Under Assertions or Waits, add: a QAN test that clicks Explain on a slowlog service selects the top row whose query does not start with `explain`, never row 1; prove it with two consecutive runs on one environment.
