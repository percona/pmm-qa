# .claude/skills/codeceptjs-migration/run.md — One --list --grep over the union of job expressions replaces the per-job loop, but run both directions

- Added: 2026-08-24
- Evidence: `run.md` step 8 prescribes `npx playwright test --list --grep '<expression>'` once per existing job. The writer ran all twelve, the initial gate re-derived the same answer with a single `--list` over the union of every active expression (95 tests in 33 files, none from the new file), and the two agreed. Separately, the runner made the reverse check pay for itself: its edit added a job rather than changing an expression, so "no existing grep changed" was true by construction, yet running the three highest-traffic expressions anyway cost one batched command and is the only thing that distinguishes a verified claim from a believed one.
- Proposed change: In `run.md` step 8, allow a single `--list --grep` over the union of all job expressions in place of the per-job loop when the question is only "does any job select this scenario", and require the reverse direction - re-listing the existing expressions after the coverage edit - even when the edit adds a job rather than modifying an expression.
