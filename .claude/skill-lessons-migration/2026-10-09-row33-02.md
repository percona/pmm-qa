# .claude/skills/codeceptjs-migration/mappings.md — A QAN page opened by goto is loaded only when a row is visible, and its copied `to` predates the page

- Added: 2026-10-09
- Applies to: mappings.md `queryAnalyticsPage.waitForLoaded`, `I.openNewTab`, `moment()` before a queued step
- Evidence: Row 33 ported `waitForLoaded` after a fresh `goto` as `waitForLoad()` (spinner count 0); in a new tab the spinner disappears ~13 s before the first row renders, failing PMM-T1142 and PMM-T1143. Separately, QAN fixes the copied link's `to` ~62 s before it sends `getReport`, so PMM-T1138 measured from `Date.now()` after the copy failed (65.7 s); the source passed only because `moment()` ran before its queued `I.amOnPage`. Also, the outer `qan-header-actions-copy-button` copies a short `/goto/` link without time params; the source's button is the in-frame `copy-link-button`.
- Proposed change: Map `waitForLoaded` after a fresh navigation to `waitUntilQanStoredMetricsLoaded`, not `waitForLoad`. Note that a CodeceptJS `const x = moment()` before a queued `I.amOnPage` captures the time before navigation; port it as a value read before `page.goto`.
