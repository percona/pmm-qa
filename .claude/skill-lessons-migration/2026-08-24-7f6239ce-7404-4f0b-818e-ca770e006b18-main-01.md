# .claude/skills/codeceptjs-migration/orchestration.md — Test-run mode does not say what happens to step 1's open-PR stop or to the final gate's subject

- Added: 2026-08-24
- Evidence: A test run of row 4 hit two undefined cases. Step 1 stops the workflow when any `migrate(` PR is open; two were open, but test-run mode cuts no publish branch, so the collision the check exists to prevent cannot occur - the parent had to adjudicate that from first principles. Separately, test-run mode skips step 5b, so the final gate ran against control's uncommitted worktree; `run.md` mandates a `startRef`/`endRef` staleness check for the final gate and explains why the initial gate omits it for a worktree subject, but nothing says which rule wins when test-run mode puts the final gate on a worktree. The reviewer substituted `git status --short` plus a diffstat and flagged that substitute as weaker than a sha.
- Proposed change: In `orchestration.md` section Test-run mode, add the open-migration-PR check to the explicit skip list, and state that a final gate whose subject is a worktree follows the initial gate's rule - `kind: worktree`, no `startRef`/`endRef`, `STALE_SUBJECT` never returned.
