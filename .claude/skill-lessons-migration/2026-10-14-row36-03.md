# .claude/scripts/migration.sh — setup proposes the wrong PS topology when the source filters on single-PS labels

- Added: 2026-10-14
- Applies to: `migration.sh setup` output, orchestration.md step 2a
- Evidence: Row 36 source filters on `cluster: 'ps-single-dev-cluster'` and environment `ps-dev` (only `--database ps` without SETUP_TYPE registers those, mysql/setup.sh:432). `migration.sh setup` printed `local: ... --database ps,SETUP_TYPE=gr`, which registers `ps-gr-dev`; its "services named" line also listed pdpgsql/pgsql for the PS-only scenario. The parent overrode it with `ps,QUERY_SOURCE=slowlog` from the nightly shard that actually serves `ps-dev`.
- Proposed change: When choosing among a shard's PS/MySQL args, match the source's environment/cluster literals against the setup type (`-dev`/`-single-dev-cluster` = no SETUP_TYPE, `-gr-dev` = gr, `-replication-dev` = replication); keep the "read the per-scenario lines" warning in step 2a.
