# .claude/skills/codeceptjs-migration/graphify.md — pass the extraction-spec subagent prompt verbatim; a scope instruction of your own can trip the shrink guard

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/graphify.md` ("Pre-migration graph updates")
- Evidence: Refreshing the Playwright graph on row 5, the parent appended "keep the node/edge set modest" to the `references/extraction-spec.md` prompt for `e2e_tests/README.md`, reasoning that a generated test-index README did not warrant many nodes. The prior graph held 34 nodes for that file; the constrained pass produced 12. The merged total went 737 -> 723, which `graphify.export.to_json`'s #479 shrink guard refuses to write, and the failure would have surfaced several steps later as a bare "refused to shrink" with nothing pointing back at the prompt. Re-running with the spec's prompt verbatim produced 65 nodes and a net 737 -> 774.
- Proposed change: State that the extraction prompt is passed verbatim, with only FILE_LIST, CHUNK_NUM, TOTAL_CHUNKS and DEEP_MODE substituted, and that adding scope or budget instructions is not a local optimisation. A per-file node count below the graph's existing count for that file shrinks the total and the guard rejects the entire write, including the files that were extracted correctly. If a file genuinely warrants fewer nodes, that is a full-rebuild decision, not a per-chunk one.
