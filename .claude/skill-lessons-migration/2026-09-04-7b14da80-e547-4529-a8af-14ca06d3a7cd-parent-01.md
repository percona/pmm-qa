# .claude/skills/codeceptjs-migration/orchestration.md — a shallow clone makes the step 1 `origin/main` merge fail as "unrelated histories"

- Added: 2026-09-04
- Applies to: `.claude/skills/codeceptjs-migration/orchestration.md` (step 1) and `.claude/skills/codeceptjs-migration/branch-workflow.md` ("Control branch preflight")
- Evidence: On row 5, `git merge origin/main` exited `fatal: refusing to merge unrelated histories` even though control already carried five prior merge commits from `origin/main`. `git merge-base HEAD origin/main` was empty, and `git rev-list --max-parents=0 origin/main` returned a commit dated the same day with an ordinary PR subject — the tell that it is a shallow boundary rather than a root. `.git/shallow` held two grafts and `git rev-list --count origin/main` was 8. `git fetch --unshallow origin` restored a real merge-base (`b6073c2c`, the second parent of the last merge commit) and the merge then applied cleanly.
- Proposed change: In the step 1 preflight, before the merge, add: if `git merge origin/main` reports "unrelated histories", check `git rev-parse --is-shallow-repository` and run `git fetch --unshallow origin`. Warn explicitly against `--allow-unrelated-histories`, which would graft two disjoint histories together and corrupt the branch permanently. Record the diagnostic: a "root" commit with a recent date and a normal PR subject is a shallow boundary, not an initial commit.
