# .claude/skills/codeceptjs-migration/audit-checklist.md — Read the server's environment when a ported helper branches on server configuration

- Added: 2026-08-24
- Evidence: Row 4's ported settings-restore helper carries a fallback that retries without two fields when the first request is rejected. Whether that fallback is dead defensive code or the only live path depends on the server's configuration, which the code cannot show. One `docker exec pmm-server env` at the final gate showed telemetry disabled in this environment, which means the fallback is the live path - upgrading the rerunnability claim from "the reset runs" to "the reset's ported error handling is itself covered by the green run". Without that check a ported branch can look exercised when it never ran, or look dead when it is the only path taken.
- Proposed change: In `audit-checklist.md`, add a check: when a migrated helper has a conditional branch keyed on server configuration, read the running server's environment and state which branch the green run actually took.
