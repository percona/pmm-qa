# .claude/skills/qa-code-review/SKILL.md — a simplification that inherits a config default must weigh the new bound, not just the lines saved

- Added: 2026-09-13
- Applies to: target only
- Evidence: A 🟡 thread on percona/pmm-qa#1419 offered, alongside an accepted comment-density finding, the alternative of dropping `waitForElement`'s second argument so it inherits `waitForTimeout: 60000` from `codeceptjs-e2e/pr.codecept.js:26`, stating the trade-off as "your call if the bounded 30s is worth the two extra lines". The author took the density half and declined this one: the explicit const is what carries the measured floor, and it bounds a genuinely missing panel to 30s rather than the inherited 60s (https://github.com/percona/pmm-qa/pull/1419#discussion_r3998543319). Confirmed in the checkout that `pr.codecept.js:26` sets `waitForTimeout: 60000`, so the suggestion doubles the wait on a real failure — a cost the thread never named. Recurrence of the check 7 measured-mechanism entry from #1414.
- Proposed change: add to check 7 that where the remedy is to drop an explicit value and inherit a config default, the thread must name the inherited value and the resulting change in the failure budget — on a flake fix a tighter explicit bound is a reason to keep the const, so lines saved is not the whole trade-off.
