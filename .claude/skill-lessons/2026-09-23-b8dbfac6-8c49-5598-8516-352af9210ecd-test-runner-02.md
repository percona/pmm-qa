# .claude/skills/linode-ha-provisioning/SKILL.md — swap from relay-installed 1.6.1 to PMM-HA-GA needs CRDs applied and PostgreSQL pinned to 17

- Added: 2026-09-23
- Applies to: target only
- Evidence: After `helm upgrade pmm-operators` to the branch deps chart (1.2.0), Helm skipped `crds/`; server-side applying every subchart CRD then blocked the upgrade with `invalid ownership metadata` on the VictoriaMetrics CRDs (templated, Helm-owned in the new VM chart) until they were labelled/annotated for `pmm-operators`; and the pmm-ha swap, which pins `pg-db.postgresVersion: 18`, crashed PG ~19 min later with `database files are incompatible with server ... initialized by PostgreSQL version 17` until `--set pg-db.postgresVersion=17,pg-db.image=...postgresql:17.6-1`.
- Proposed change: Extend the swap section's ordered steps: apply non-VM subchart CRDs server-side before upgrading `pmm-operators`, and pin `pg-db.postgresVersion`/`pg-db.image` to the installed release's values (`helm get values --revision 1 -a`) when swapping over an existing PG 17 install.
