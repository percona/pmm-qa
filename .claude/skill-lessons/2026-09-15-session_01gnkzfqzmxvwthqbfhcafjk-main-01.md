# .claude/skills/qa-code-review/references/playwright-suite.md — an "accept either name" assertion is a coverage loss the review passed

- Added: 2026-09-15
- Applies to: .claude/skills/qa-code-review/references/playwright-suite.md (Assertions)
- Evidence: Three AI reviews read the diff that introduced `waitForAnyMetric([data, replicaStatusAliases[data]])` on percona/pmm-qa#1436 and none faulted it: CodeRabbit raised only the helper's polling timeout, and a claude[bot] thread cited the call approvingly as already stating the intent a comment restated. The author later removed the helper in `42ed54e` because "accepting either metric name weakened what PMM-T2028 asserts", asserting the 8.4 names outright (https://github.com/percona/pmm-qa/pull/1436#discussion_r4018206726). The Assertions table sets a *ported* assertion's strength from its CodeceptJS source, and the Structure rules require a `versionGate` over an inline version `if`, but nothing covers a native assertion widened to pass under either version.
- Proposed change: Add an Assertions row — an expectation widened to accept a union of values (an alias array, an OR matcher, a `waitForAny…` helper) so the test passes under more than one version or environment is a coverage loss, 🟡: ask for the value correct for the configuration the tag actually provisions, or a `versionGate` keyed by the `PMM-T` id. Relates to the queued investigator.md entry on the same construction from the authoring side.
