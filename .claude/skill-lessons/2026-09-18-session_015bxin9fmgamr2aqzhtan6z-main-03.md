# .claude/skills/qa-code-review/references/playwright-suite.md — the reuse rule covers a new page-object method but not a test assertion that re-implements one

- Added: 2026-09-18
- Applies to: .claude/skills/qa-code-review/references/playwright-suite.md (Page objects)
- Evidence: Three AI reviews on percona/pmm-qa#1446 read an inline `.count()`-against-a-budget assertion in `e2e_tests/tests/dashboards/nodesOverviewDashboard.test.ts` and raised its semantics — visibility filtering, the budget literal, a second budget in the POM — while none raised that it should not exist. The maintainer did: "I believe we have methods in place that does this same validation created by Peter" (https://github.com/percona/pmm-qa/pull/1446#discussion_r4048747835), and after the author established the difference (https://github.com/percona/pmm-qa/pull/1446#discussion_r4048807025) the merged test calls `dashboard.verifyAllPanelsHaveData(dashboard.os.nodesOverview.noDataMetrics)` (https://github.com/percona/pmm-qa/pull/1446#discussion_r4049134183). That method is `e2e_tests/pages/dashboards/dashboards.page.ts:210` with 17 call sites, and the Page objects row "Check `pages/base.page.ts` before adding a method" only fires on a diff that adds a page method.
- Proposed change: Widen that row — an assertion written inline in a test is read against `dashboards.page.ts` and `base.page.ts` as well, and one that re-implements an existing `verify…` method is a finding even where the inline form is correct; where the existing method would change what the test covers, the finding is the choice, stated for the author.
