# .claude/agents/investigator.md — do not mine past CI runs for recurrence with get_job_logs tail windows

- Added: 2026-09-02
- Applies to: target only
- Evidence: To check whether a nightly failure recurred on earlier dates, two `get_job_logs` calls were made with `tail_lines` of 60 then 185 against the same failed job. Both returned only post-test log noise (artifact uploads, git credential cleanup, post-job steps) because the Launchable gate block naming the failing test sits just above that window, so neither call yielded the test name; together they consumed roughly 25k tokens of context and the attempt was abandoned mid-investigation as low-yield.
- Proposed change: In the recurrence/dedup guidance, say that the failing test names for a past run come from that run's `junit_*` artifact or its Launchable test-session id (both printed in the job log the first time it is read), not from re-fetching job logs with a larger `tail_lines`; a tail window big enough to reach the gate block is not worth the context.
