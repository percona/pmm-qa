# .claude/agents/investigator.md — poll a run's jobs, not the run object's status

- Added: 2026-09-16
- Applies to: .claude/agents/investigator.md
- Evidence: A watch polling `actions/runs/<id>` treated the run as still waiting for an hour: the run object reported `"status": "queued"` with `updated_at` frozen at creation, while its jobs endpoint showed 25 completed successfully, 2 running and 8 queued. This repo's e2e runs call reusable workflows, where the run-level status lags, so a watch keyed on it stays silent and would never have seen completion either.
- Proposed change: When waiting on or judging an Actions run, read `actions/runs/<id>/jobs` and derive state from the jobs (none pending = finished, any non-success conclusion = failure); treat the run object's `status`/`conclusion` as unreliable for runs that call reusable workflows.
