# .claude/skills/qa-code-review/references/playwright-suite.md — read a new page object against a sibling in the same folder

- Added: 2026-09-14
- Applies to: .claude/skills/qa-code-review/references/playwright-suite.md
- Evidence: The review passed three new OS page objects that built `metrics` from a local `panelNames` const and a `.map()`, where every existing dashboard in that folder declares `metrics` as an inline literal. The human reviewer raised the same comment on all three — "There is no real gain to have this, why not inline it as we have done with others dashboards?" (https://github.com/percona/pmm-qa/pull/1417#discussion_r4003728273, https://github.com/percona/pmm-qa/pull/1417#discussion_r4003729069, https://github.com/percona/pmm-qa/pull/1417#discussion_r4003730036); the merged files declare it inline, e.g. `e2e_tests/pages/dashboards/operating-system/diskDetails.ts:7`. The Structure rule "a helper or const with one caller belongs in its caller" covers the const but did not fire.
- Proposed change: Add a Page objects row — a new page object is read against a sibling in the same folder and declares the same members in the same shape; a construction no sibling uses (a local const plus `.map()` to build `metrics`) is a finding even when the result is correct.
