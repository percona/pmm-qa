# .claude/skills/ui-evidence/SKILL.md — pw-screenshot.js only runs in the cloud image (hardcoded /opt/pw-browsers Chromium, no local `playwright` resolution)

- Added: 2026-09-23
- Applies to: .claude/scripts/pw-screenshot.js and pw-record.js as used by ui-evidence on a local desktop checkout
- Evidence: On a macOS checkout, `node .claude/scripts/pw-screenshot.js <actions-run-url> out.png` first failed with "Cannot find module 'playwright'" (fixed by NODE_PATH=cli/node_modules), then with "executable doesn't exist at /opt/pw-browsers/chromium" because executablePath is hardcoded with no env override; a GitHub Actions screenshot only worked from an untracked patched copy placed beside the script, since it requires ./lib/* relatively.
- Proposed change: Make the script use /opt/pw-browsers/chromium only when it exists (or honor a PW_CHROMIUM_PATH env var), falling back to Playwright's default browser, and document NODE_PATH=cli/node_modules (or e2e_tests/node_modules) for local runs in ui-evidence.
