# .claude/skills/jenkins-builds/SKILL.md — A Jenkins build can report on a GitHub Actions run it did not dispatch

- Added: 2026-09-18
- Applies to: target only
- Evidence: Ten parallel lanes dispatched one workflow file within ~6 seconds; one build dispatched a run at 22:11:04 but polled a sibling's run created at 22:11:08, so the failure detail it reported belonged to another lane. Both runs happened to fail, so the red/green verdict was accidentally right and the mis-attribution was invisible. The existing "never extend a verified range by adjacency" section covers numeric adjacency, not dispatch collision.
- Proposed change: Extend the attribution section — when a build dispatches a workflow, confirm the run it reports on by matching a lane-unique field in the run's env group (e.g. `SERVER_IP`/`PMM_UI_URL`) against the dispatch payload before quoting its result or its failure detail.
