# .claude/skills/pmm-framework-change/SKILL.md — `make check` fails for a harness reason, so baseline it on `main` before reading it as a regression

- Added: 2026-08-28
- Applies to: target only
- Evidence: reviewing a PR that changed `pmm-framework/lib/config.sh`, `make check` in `qa-integration/pmm_qa/pmm-framework` exited non-zero with `*.sh: *.sh: openBinaryFile: does not exist (No such file or directory)` / `make: *** [lint] Error 2`, because the `lint` target globs `*.sh` at the framework root where no top-level `.sh` files exist and the glob is passed through unexpanded. The identical command on `main` failed identically, so it was not caused by the diff. Running `bats tests` directly gave the real result: 50/50 passing.
- Proposed change: in the "Always run `make check`" section, note that a non-zero `make check` may be the `lint` target's unexpanded `*.sh` glob rather than the change under review — run the same command on `main` (or a `git worktree` of it) first to establish the baseline, and fall back to `bats tests` directly to get the suite result when `lint` aborts before the tests run.
