# .claude/skills/qa-code-review/SKILL.md — on a migration PR, "pre-existing" and "inconsistent constant" are judged against the CodeceptJS source scenario

- Added: 2026-09-18
- Applies to: .claude/skills/qa-code-review/SKILL.md (check 1)
- Evidence: Three maintainer replies on percona/pmm-qa#1446 rejected findings raised against a *new* Playwright file, which check 1's "also present on `main`" test cannot reach because the file itself is new. A CodeRabbit coverage finding — a silently ignored `environment` filter would still pass — was declined as inherited: `verifyThereAreNoGraphsWithoutData(4)` at `codeceptjs-e2e/tests/dashboards/verifyNodesOverviewDashboard_test.js:23` asserts the same thing on the same URL, measured live at 0 empty panels unfiltered, 2 filtered and 60 with the label absent, against a budget of 4 (https://github.com/percona/pmm-qa/pull/1446#discussion_r4041848230, https://github.com/percona/pmm-qa/pull/1446#discussion_r4041848393). A claude[bot] 🔵 that the dashboard now carries two no-data budgets — the POM's `acceptableNoDataCount = 3` and the ported literal `4` — was corrected on provenance: the two belong to two different scenarios, and the POM value's only CodeceptJS consumer is already retired, so neither governs the other (https://github.com/percona/pmm-qa/pull/1446#discussion_r4041848673).
- Proposed change: In check 1, apply the pre-existing test on a migration PR to the CodeceptJS scenario being ported, cited as `file:line`, rather than to the new file's own path; and require each of two constants said to govern one dashboard to be traced to the scenario that owns it before the inconsistency is raised. This does not touch check 7's rule that "it is a port" defers no duplication finding — it governs coverage and constant-provenance findings only.
