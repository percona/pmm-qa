# .claude/skills/repos/SKILL.md — a full `git fetch` outruns the Bash tool's default timeout; use the GitHub MCP to read remote state

- Added: 2026-08-25
- Evidence: `git fetch origin --prune` in the pmm-qa checkout was killed at the Bash tool's 2-minute default (exit 143) before listing any ref; the same question — which remote branches exist — was answered immediately by `mcp__github__list_branches`, and "does this path exist on main" by `mcp__github__get_file_contents`, with no fetch at all. A re-run wrapped in `timeout 300` and backgrounded did succeed, confirming slowness rather than a network failure.
- Proposed change: in the "GitHub access — MCP-first" section, add that reading *remote* state (which branches or tags exist, whether a path exists on a ref) belongs to the MCP tools too — `list_branches`, `list_tags`, `get_file_contents` — and that a local `git fetch` is only for work that needs objects in the checkout. When a fetch is genuinely needed in this repo, fetch the single branch (`git fetch origin <branch>`) or give it an explicit long timeout / background run, because a full `--prune` fetch of pmm-qa's ~120 branches and tags exceeds the Bash tool's 2-minute default.
