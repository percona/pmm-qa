# .claude/agents/investigator.md — a duration regression is a bug to root-cause, never a budget to resize

- Added: 2026-09-11
- Applies to: target only
- Evidence: The classification tree has no branch for "the step got much slower", so a setup that went from ~9 min to 43.8-57.2 min was classified as test-infrastructure and "fixed" by raising the job timeout 60 -> 90. The user rejected it: the same pmm-qa commit and the same runner image had done that setup in 9m14s the previous day, so the budget was never the defect. The real cause was degraded egress on individual runner VMs (identical fetches at 7.9-13.2 MB/s vs 1.2 MB/s decaying to 44 kB/s), which a bigger timeout would have hidden while each job kept re-downloading ~1.43 GB of identical packages once per container.
- Proposed change: In step 3's decision tree, add that when a step regressed in duration rather than failing outright, the investigation must first find the most recent run where it was fast and diff the controlled variables (code SHA, runner/base image, host, concurrent load) to locate the change; raising a timeout, retry count or other budget to fit the observed duration is never the classification and never the fix.
