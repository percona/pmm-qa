# .claude/skills/pmm-framework-change/SKILL.md — pmm-agent setup's single positional sets node-address, not node-name

- Added: 2026-09-18
- Applies to: target only
- Evidence: Four `pmm-agent setup … {{ container_name }}` calls in a shared client-install task were read as setting the node name. The positionals are `[node-address] [node-type] [node-name]` and node-name defaults to `os.Hostname()`; the containers are created without `--hostname`, so each node registered under the container's docker short ID — a new identity on every re-provision, and a permanent orphan in `label_values` after each retry.
- Proposed change: Record the positional order and the `os.Hostname()` default, and require `PMM_AGENT_SETUP_NODE_NAME` (or an explicit container `hostname:`) whenever a setup registers a client from inside a container.
