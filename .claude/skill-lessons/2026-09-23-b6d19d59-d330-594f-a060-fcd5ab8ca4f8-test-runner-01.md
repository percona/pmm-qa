# .claude/skills/linode-ha-provisioning/SKILL.md — PMM-HA-GA deps swap via helm upgrade breaks the PG operator; fresh-install instead

- Added: 2026-09-23
- Applies to: .claude/skills/linode-ha-provisioning/SKILL.md
- Evidence: `helm upgrade pmm-operators` from the relay's pmm-ha-dependencies 1.0.0 to PMM-HA-GA 1.2.0 left PG operator 3.1.0 in CrashLoopBackOff (`no matches for upstream.pgv2.percona.com/v1beta1`) because Helm never installs subchart `crds/` on upgrade; recovering took a documented-order uninstall, clearing PerconaPGCluster/perconapgbackup finalizers, deleting operator CRDs and PVCs, renaming pmm-secret VMAGENT_* keys to PMM_HA_VM_*, then a fresh install (~25 min).
- Proposed change: In the chart-swap section, say that when the deps chart crosses a PG operator major (2.x to 3.x) the swap must be a fresh install (uninstall pmm-ha then pmm-operators, delete operator CRDs and PVCs, rename the TP secret keys, install deps then pmm-ha with `--set haproxy.service.type=LoadBalancer`), not `helm upgrade`.
