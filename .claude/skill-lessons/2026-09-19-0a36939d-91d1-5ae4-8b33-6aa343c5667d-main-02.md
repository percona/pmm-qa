# .claude/skills/qa-code-review/SKILL.md — an "empty after filtering" assertion is satisfied by a list that never populated

- Added: 2026-09-19
- Applies to: .claude/skills/qa-code-review/SKILL.md and its playwright-suite.md / codeceptjs-legacy.md references
- Evidence: a scenario typed a character into a search field and asserted the filtered result count equals 0; measured on a live server the panel holds 0 items right after the loading spinner detaches and 21 a few seconds later, so the scenario passed in 4.4s on the first probe and asserted nothing about the search.
- Proposed change: add a review rule that an assertion of absence or "filtered to zero" must be preceded by an assertion that the unfiltered precondition holds, since otherwise the test cannot distinguish a working filter from a list that has not loaded.
