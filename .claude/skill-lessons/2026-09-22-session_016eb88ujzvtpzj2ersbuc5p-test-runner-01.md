# .claude/skills/linode-docker-provisioning/SKILL.md — test an unmerged pmm PR with no FB build by swapping pmm-managed binaries into the stock server image

- Added: 2026-09-22
- Applies to: target only
- Evidence: PMM-15191's feature build never produced an image (the pmm-submodules FB PR carried only a JNKPercona "outdated source branches" comment, no check runs, no `perconalab/pmm-server-fb:PR-<n>-*` tag), so the fix was exercised by building `pmm-managed` + `pmm-managed-init` from the PR head and from the PR's merge-base in a `golang` container on the VM and bind-mounting each pair over `/usr/sbin/` in `perconalab/pmm-server:3-dev-latest`; a first build without version ldflags made pmm-managed panic "pmm-managed version is not set during build" and supervisord crash-loop it, costing a full build-and-switch cycle.
- Proposed change: add a section covering this A/B binary-swap for a `managed/`-only change when no FB image exists — build both arms with the `version.Version`/`PMMVersion`/`FullCommit` ldflags from `managed/Makefile` (a binary without them panics at startup), confirm `managed/models/database.go` is unchanged between the base commit and the image's commit so both arms share a DB schema, `docker stop` before `docker rm` when recreating on the same `pmm-data` volume, and print `pmm-managed --version` after each switch so every result names the arm it came from.
