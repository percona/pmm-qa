# .claude/skills/ui-evidence/SKILL.md — the evidence helpers hide and mutate PMM's update state, so they cannot be used to test upgrade UI

- Added: 2026-09-03
- Applies to: target only
- Evidence: Testing an upgrade ticket, a `pw-screenshot.js` capture of `/pmm-ui/updates` showed "Your PMM instance is up-to-date" with no Update button while the API reported `update_available: true`; both `pw-screenshot.js` and `pmm-ui-login.js` install `page.route("**/v1/server/updates?force=**")` answering `update_available:false` so the update modal stays out of evidence shots. That stub also removes the state under test, and it read as a product blocker for several minutes. Separately, after a `pmm-ui-login.js` run the server reported `snoozed_pmm_version` set and `snooze_count: 1`; `useSnooze` then suppresses the update popup entirely, and past `snooze_count >= 1` the UI switches from the centered modal to a bottom-right snackbar. `PUT /v1/users/me` clears the version but not the count, so only a fresh data volume restores the pristine popup. A plain in-script `POST /graph/login` left `snooze_count: 0`.
- Proposed change: Add a warning to the skill that the two helpers stub `/v1/server/updates` (and `pmm-ui-login.js` also stubs `/v1/users/me`), so neither may be used to observe update/upgrade UI; such a flow needs its own script that logs in with `POST /graph/login` and installs no routes, plus a fresh volume when the pristine update popup is required.
