# CLAUDE.md — A grep hit proves a string exists, not that it is on the path under investigation

- Added: 2026-09-18
- Applies to: all skills
- Evidence: Three root-cause claims in one session were asserted from a grep and later refuted: a dashboard variable's `role!="sentinel"` filter (the playbook labels those services `role=primary`/`role=replica`), a `[PDPGSQL_PGSM_CONTAINER]=` assignment in one setup file (the consuming playbook is not the one that setup function runs), and a stale `itemCount` (the defect was the unit of iteration). Each cost a wrong statement to the user before evidence arrived.
- Proposed change: Add a House style rule — before asserting a mechanism, trace producer to consumer and name the call site that reads the value; a grep locates a candidate, it does not establish that the code runs on the path being diagnosed.
