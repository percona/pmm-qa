# .claude/skills/qa-code-review/SKILL.md — replacing a fetch must preserve the filtering the old mechanism did implicitly

- Added: 2026-09-21
- Applies to: .claude/skills/qa-code-review/SKILL.md, .claude/agents/investigator.md
- Evidence: `gpg --recv-keys <fpr>` + `gpg --export <fpr>` was replaced with "download the vendor bundle, assert the fingerprint is present, import the bundle". The data looked equivalent, but the old form trusted exactly the named keys while the new one trusted whatever else the file carried. Reviewers flagged it; reproduced by appending a locally generated key to the genuine bundle, which yielded a keyring trusting both. The presence assertion gave false confidence that the property had been kept.
- Proposed change: When a change swaps out how an artifact is obtained, ask what the old call selected as well as what it returned, and carry that selection across; a check that the expected item is present is not a check that nothing else is.
