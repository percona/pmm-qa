# CLAUDE.md — put design rationale in the artifact that is not loaded into context

- Added: 2026-08-25
- Evidence: A hook change was documented three times over — a 3-line code comment, a 75-word addition to `.claude/skills/skill-gardener/SKILL.md`, and the PR body — all explaining the same rejected alternative. The user asked whether it could be simplified. SKILL.md is read into context on every invocation of that skill, so rationale there is a recurring token cost paid by every future session; the hook script is executed, never read into context, so the same words there cost nothing. Cutting SKILL.md to a one-clause factual update (+75 words to +8) and keeping a two-line comment in the script lost no information a maintainer needs.
- Proposed change: add to the House style section that design rationale — why a rejected alternative was rejected, why a constraint exists — belongs in the code or config that implements it, not in a skill or agent file, because those are loaded into context on every invocation while scripts are not. A skill file should state what the mechanism is; the script should state why it is that way.
