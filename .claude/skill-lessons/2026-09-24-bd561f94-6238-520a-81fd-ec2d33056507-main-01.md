# .claude/agents/investigator.md — get_job_logs failed_only silently truncates a non-empty failure list at 30 jobs

- Added: 2026-09-24
- Applies to: investigator.md "Being invoked" enumeration tip, .claude/skills/fb-tests/SKILL.md, .claude/skills/repos/SKILL.md tool map
- Evidence: On a 55-job FB Tests run, `get_job_logs` `failed_only: true` reported `failed_jobs: 8, total_jobs: 30` (all E2E), hiding 6 more failed CLI jobs that only `actions/runs/<id>/attempts/1/jobs?per_page=100` showed; the partial list looked complete, unlike the zero-result case already captured.
- Proposed change: Require the failure list to come from a full job listing (`per_page=100`, `total_count` checked) whenever `get_job_logs` reports `total_jobs` below the run's real job count, not only when it reports zero failures.
