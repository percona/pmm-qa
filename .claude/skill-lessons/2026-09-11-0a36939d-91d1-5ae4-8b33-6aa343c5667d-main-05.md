# .claude/skills/linode-docker-provisioning/SKILL.md — pass scripts to the box on stdin or base64, never as nested quoted shell

- Added: 2026-09-11
- Applies to: target only
- Evidence: A `sed -i -E` carrying a URL regex, sent as `run.sh ... -- "docker exec <c> sh -c '...'"`, lost its quoting through the three shell layers and rewrote a container's apt sources into `E: Malformed entry 1 in sources file ... (URI parse)`. The command still exited 0, so the corruption only surfaced on the next `apt-get update`. Writing the same script to a file and invoking it (`base64 -d > /root/s.sh`, then `docker exec -i <c> sh -s ARG < /root/s.sh`) worked first try and stayed readable.
- Proposed change: In "Calling run.sh", add that any command containing quotes, regexes or `$` must be shipped as a file — `base64 -w0` locally, decode on the box, and feed containers with `docker exec -i ... sh -s <args>` on stdin — because each nesting layer strips a quoting level silently and the mangled command can still exit 0.
