# .claude/skills/skill-gardener/SKILL.md — check a hook event's output schema before proposing a hook that uses it

- Added: 2026-08-25
- Evidence: Entry 02 of this same day proposed fixing the gardener's trigger placement with a `Stop` hook that re-injects the observer reminder via `additionalContext`. That is not possible: only `PostToolUse`, `PostToolUseFailure`, `Notification`, `SessionStart`, `Setup`, `SubagentStart` and `UserPromptSubmit` carry an `additionalContext` field in the installed CLI's `hookSpecificOutput` union. `Stop`'s only channel to the model is `decision: "block"` plus `reason`, which forces the model to continue and so reintroduces the stop-time pass the skill exists to avoid. The proposal was asserted from the event name alone and only caught when the schema was actually read; the implemented fix used `PostToolUseFailure` instead, which fires when evidence exists and needs no extra pass.
- Proposed change: this entry supersedes entry 02's proposed mechanism — treat that one as resolved by the `PostToolUseFailure` hook rather than implementing a `Stop` hook. Add to the skill that a lesson proposing new gardener automation must name the event's actual output channel, verified against the installed CLI's schema, before the entry is written: an event existing in the hook enum does not mean it can inject context, and `Stop` specifically cannot.
