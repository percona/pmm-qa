# .claude/skills/linode-docker-provisioning/SKILL.md — remove the containers a failed pmm-framework run left behind before retrying it

- Added: 2026-09-14
- Applies to: .claude/skills/linode-docker-provisioning/SKILL.md
- Evidence: After a `pmm-framework` mysql setup failed at the pmm-client install, an identical re-run failed much earlier and for a different reason — `TASK [Prepare Container for MySQL 8.0+]` could not `docker run --name mysql_pmm_9_7_1` because the half-configured container from the first attempt still existed. `docker rm -f mysql_pmm_9_7_1` and a third run completed cleanly. The second run's failure looked like a new bug and cost a full setup cycle to read.
- Proposed change: In step 3, add that a failed `pmm-framework` run leaves its partially configured containers behind and the playbooks do not reclaim the names, so before any retry remove them (`docker rm -f <name>`, or `docker ps -a` to find them) — a retry's first failure is otherwise a name conflict masking the original cause.
