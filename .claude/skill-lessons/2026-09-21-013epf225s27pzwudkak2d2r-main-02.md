# .claude/agents/investigator.md — re-check the submodules PR's comments immediately before posting the FB triage comment

- Added: 2026-09-21
- Applies to: target only
- Evidence: Two FB runs on pmm-submodules PR #4475 (06:22 and 07:02) each fired this Routine, so two Investigator sessions triaged the same deterministic failure concurrently. The step-1 comment read at the start of the later session was clean; the sibling posted its triage at 07:30:58, mid-investigation, and the later session posted a near-identical second comment at 07:34:20. Step 1 makes a prior triage comment a stop condition and step 5 requires re-running the sweep immediately before `create_pull_request`, but no re-check guards the comment itself — which is the artifact that actually gets duplicated on a verdict needing no PR.
- Proposed change: In the "Relay the result" FB bullet, require re-reading the submodules PR's comments (`pull_request_read`, `get_comments`) immediately before `add_issue_comment`, applying step 1's stop condition to what came back; if a sibling triage naming the same failing tests is already there and still accurate, add only genuinely new evidence as a short reply, or post nothing and report the duplicate in the run output.
