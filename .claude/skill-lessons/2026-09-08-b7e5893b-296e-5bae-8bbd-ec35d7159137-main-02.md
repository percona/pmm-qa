# .claude/agents/investigator.md — `get_job_logs` with `tail_lines: 1` names every failed job in a past run for almost nothing

- Added: 2026-09-08
- Applies to: .claude/agents/investigator.md
- Evidence: Deciding whether a nightly setup-shard timeout was shard-specific needed only the set of failed job names from two earlier runs; `get_job_logs` (`failed_only: true`, `tail_lines: 1`) returned each job's name with one trailing line apiece and showed a different shard had failed each night (ps-replication, ps-gr, extra-pxc), with no run-logs zip and no large tail.
- Proposed change: Next to the existing "don't mine past runs by growing tail_lines" rule, state that `failed_only: true` with `tail_lines: 1` is the cheap way to enumerate a past run's failed *job* names, and that a different job failing each run is the tell for a contended or environmental failure rather than a defect in one shard.
