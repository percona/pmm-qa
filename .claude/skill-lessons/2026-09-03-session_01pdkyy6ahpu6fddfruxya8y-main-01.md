# .claude/skills/linode-docker-provisioning/SKILL.md — GF_SECURITY_ADMIN_PASSWORD does not set the admin password on a PMM server image

- Added: 2026-09-03
- Applies to: target only
- Evidence: Step 2's `docker run` passes `-e GF_SECURITY_ADMIN_PASSWORD='$ADMIN_PASSWORD'`, but every subsequent API call returned `Invalid username or password`, and so did `admin:admin`. The grafana process did have the variable (`/proc/<pid>/environ`), and the log showed `Config overridden from Environment variable var="GF_SECURITY_ADMIN_PASSWORD=*********"` — yet `select login, created, updated from "user"` in the container's `grafana` DB showed the admin row created months earlier, at image build time, with `updated` equal to `created`. Grafana 11.6 only applies that variable when it creates the admin user, and the PMM image ships the user pre-created, so a fresh `/srv` volume does not help. Probing with wrong passwords also tripped Grafana's brute-force lockout ("login for user temporarily blocked"), which then masks a subsequent correct password for ~5 minutes. The image's own `/usr/local/sbin/change-admin-password <pw>` (a `grafana cli admin reset-admin-password` wrapper) sets it successfully after readyz.
- Proposed change: In step 2, keep the env var but add `docker exec pmm-server change-admin-password "$ADMIN_PASSWORD"` after the readyz wait as the step that actually sets the password, and warn that repeated failed logins lock the account for several minutes, so credentials should be verified once rather than probed.
