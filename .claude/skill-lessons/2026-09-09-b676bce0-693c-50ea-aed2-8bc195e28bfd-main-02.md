# CLAUDE.md — poll a harness background task on its exit marker, not only on a content string

- Added: 2026-09-09
- Applies to: all agents and routines (House style)
- Evidence: A `run_in_background: true` command had already finished and its output file ended with `[exited with code 0]`, but the poll loop only matched content strings ("VM ready", "IP="), so it ran 20 iterations of 30s and burned about ten minutes after the work was done.
- Proposed change: Add a House style rule that a loop watching a harness background task must break on `[exited with code` as well as its content marker, and that the task-completion notification the harness delivers on its own is preferred over an interval poll of the output file.
