# .claude/skills/qa-code-review/SKILL.md — a missing-secret/CI-reachability finding must account for Jenkins-only entry points

- Added: 2026-09-09
- Applies to: .claude/skills/qa-code-review/SKILL.md
- Evidence: percona/pmm-qa#1255, discussion_r3969259017. `claude[bot]` raised a 🔴 (discussion_r3968905485) that `PMM-T2105` would fail because none of its RDS/AWS credential env vars were set by any workflow under `.github/workflows/`, and the author initially applied a fix wiring them into `ha-e2e-tests.yml`. The author later corrected both the finding and their own fix: the `@pmm-ha` suite actually runs from the `pmm3-ha-e2e-tests-gha` Jenkins pipeline in `Percona-Lab/jenkins-pipelines`, which already binds all five credentials in its own `environment {}` block and never dispatches the repo's GitHub workflow at all — so the premise ("not set by any workflow under `.github/workflows/`") was true but did not establish what it was used to argue, and the applied fix wired secrets into a dead, `workflow_dispatch`-only path and was reverted.
- Proposed change: state that a finding asserting a test is unreachable, or its credentials/config are missing, because nothing under `.github/workflows/` provides them is incomplete on its own — several suites (at least `@pmm-ha`) run from a Jenkins pipeline in `Percona-Lab/jenkins-pipelines` that this repo's workflows never dispatch, so the search has to also rule out (or the review has to flag as unverified) an external pipeline entry point before treating a grep of this repo's workflows as proof of unreachability.
