# .claude/skills/repos/SKILL.md — `actions_list` has no `fields` parameter; a LARGE perPage is what keeps a run listing out of context

- Added: 2026-09-15
- Applies to: .claude/skills/repos/SKILL.md
- Evidence: Entry -03 from this session proposed a `fields` filter on `list_workflow_runs`, but `actions_list`'s schema has no such parameter (only `list_pull_requests` does); `perPage: 5` returned inline and cost ~15k tokens of squashed commit bodies, while `perPage: 40` exceeded the cap, spilled to a file, and answered the same question for ~200 tokens after a local `python3 -c json.load`.
- Proposed change: In the "Big listings overflow the result cap" section, state that for `list_workflow_runs` the spill is the cheap path and a small `perPage` is the expensive one — request a large page deliberately and parse the saved file; supersede entry -03's `fields` suggestion, which names a parameter the tool does not accept.
