# .claude/skills/linode-docker-provisioning/SKILL.md — a comparison arm checking out a pre-change SHA needs the shallow clone deepened first

- Added: 2026-09-22
- Applies to: .claude/skills/linode-docker-provisioning/SKILL.md, .claude/agents/investigator.md
- Evidence: Recurrence of the known shallow-clone gap, now in the A/B-arm form. Investigator's "run the pre-change revision on the same provisioned box" control shipped `git checkout <sha>^` to the VM; the relay's clone is shallow, so it died instantly with `error: pathspec '<sha>^' did not match any file(s) known to git` and the whole detached launch-and-poll cycle had to be repeated. Resolving the parent locally and running `git fetch origin <full-sha> && git checkout <full-sha>` on the box then worked, and the arm passed in 31s.
- Proposed change: In the "A comparison run must prove which code each arm ran" paragraph, add that revision expressions (`^`, `~`, `HEAD~1`) must be resolved to a full SHA in this environment before being shipped, since a shallow clone cannot resolve them, and that the arm must `git fetch origin <full-sha>` (or `git fetch --unshallow origin`) before `git checkout` — checking out a whole pre-change revision this way is an alternative to the existing "materialise the file locally and base64 it over" remedy when the arm needs the full tree.
