# .claude/skills/linode-docker-provisioning/SKILL.md — a 409 from `/linode/provision` is a run_id collision, and its "poll" hint hands you someone else's live VM

- Added: 2026-09-09
- Applies to: .claude/skills/linode-docker-provisioning/SKILL.md, and the run_id guidance in .claude/agents/investigator.md
- Evidence: Two Investigator Routine sessions fired the same evening both picked run_id `nightly-e2e-<date>`; the relay answered the second `/linode/provision` with `409 {"status":"provisioning","hint":"already running — poll /linode/provision-result"}` (not the documented 502 "already has a state file"), polling as the hint said returned a box the other session was actively using, and recreating `pmm-server` plus its `pmm-data` volume on it invalidated both reproductions — the only tell being `/root` scripts and containers this session never created.
- Proposed change: In "Pick a run_id", treat 409 exactly like 502 — a claimed run_id, never a poll — and require a run_id that carries the failing workflow's GitHub run number (`nightly-e2e-run337`) rather than only a date, since one night's failures fire the Routine several times; add `ls /root` + `docker ps -a` as a first check on any box handed back for an already-claimed id.
