# .claude/hooks/ — Jenkins and Actions log pitfalls already documented were re-hit because the owning guidance never loaded

- Added: 2026-09-18
- Applies to: .claude/skills/jenkins-builds/SKILL.md and .claude/agents/investigator.md
- Evidence: A main-agent triage session made ~40 Percona-Jenkins-MCP calls without invoking `jenkins-builds`, then reported three still-running lanes as green off `SUCCESS` rows with 757 ms and -16 ms durations — the exact tell `jenkins-builds/SKILL.md:25` describes ("a near-zero stage duration (723 ms for a suite) and a negative one"). The same session paged one GitHub Actions job log at 40, 130, 175, 205, 215 and 255 `tail_lines`, reaching only cleanup noise, which `investigator.md:20` and `:26` already forbid ("Stop at one tail attempt", "Two tails ... cost ~25k tokens").
- Proposed change: Add a hook that loads `jenkins-builds` on first use of a `mcp__Percona-Jenkins-MCP__*` tool and surfaces the `tail_lines` rule on first use of `get_job_logs`, rather than restating either rule more forcefully.
