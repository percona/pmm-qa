# .claude/agents/investigator.md — do not predict the base branch will hit a failure without checking the test runs there

- Added: 2026-09-08
- Applies to: target only
- Evidence: A standing-down comment on a PR attributed a red check to a dependency bump already merged to main, and stated that main's next scheduled run "should hit it too". Main's cron ran the next morning on a commit containing that bump and the same suite, and passed, falsifying the prediction publicly on the PR. The suites select tests per run through a subsetting service, so a test failing on one run need not be selected on another, and this was never checked before the claim was written.
- Proposed change: In the standing-down comment, confine the claim to what was verified (which files the diff touches and whether the failing job reads them). Before asserting the base branch will reproduce a failure, confirm the failing test was actually executed in the comparison run -- per-run subsetting and tag greps can exclude it -- and otherwise state the attribution without a forecast.
