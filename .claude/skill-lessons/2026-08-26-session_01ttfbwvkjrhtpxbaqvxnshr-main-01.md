# AGENTS.md — verify an external CLI's real command surface before writing a skill around its docs

- Added: 2026-08-26
- Evidence: A `test-health` skill was authored from the CloudBees Smart Tests documentation, whose AI-assistance and CLI-reference pages describe a `smart-tests view flaky-tests | never-failing-tests | longest-tests | test-results` family. Installing it failed outright — the `smart-tests` package returns 404 from public PyPI, so no version exists to pin — and the CLI this repo actually installs in CI (`launchable~=1.0`, resolved 1.124.4) has no `view` command at all; `--help` showed the real surface as `stats`, `inspect`, `gate`, `detect-flakes`, `subset`, `record`, `compare`. Three already-written files (a SKILL.md, a reference leaf, and an agent) had to be rewritten around the actual commands. The same `--help` pass also found `gate`, the quarantine-enforcement command the docs attributed to the unavailable CLI, already present in the installed one.
- Proposed change: In the development-workflow guidance, require that a skill or agent wrapping an external CLI be written against the installed binary — install it and read `--help` for the subcommand tree before documenting any command — rather than against vendor documentation, which may describe an unreleased or separately-packaged tool. Where the tool cannot be authenticated while authoring, document command names and flags as verified and mark output field names explicitly unverified, with an instruction to print one payload and correct them on the first authenticated run, instead of inventing plausible keys.
