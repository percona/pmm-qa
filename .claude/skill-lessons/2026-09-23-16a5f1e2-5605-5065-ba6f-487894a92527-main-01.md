# .claude/skills/repos/SKILL.md — get_job_logs failed_only sees only the first 30 jobs of a run

- Added: 2026-09-23
- Applies to: .claude/skills/repos/SKILL.md tool map and every agent that enumerates failed jobs (investigator, fb-reporter)
- Evidence: On a failed 240-job nightly-test-suite run, `get_job_logs` with `failed_only: true` returned `failed_jobs: 0, total_jobs: 30, "No failed jobs found"`; the one failed job was only found on page 3 of `actions_list` `list_workflow_jobs` (`perPage: 100`).
- Proposed change: In the repos tool map (and the investigator CI-trigger paragraph that recommends `failed_only` + `tail_lines: 1` to enumerate failures), state that `failed_only` inspects only the first page of jobs, so a `total_jobs` of 30 or a failed run reporting zero failed jobs means enumerate with `list_workflow_jobs` `perPage: 100`, paging to `total_count`, and filter `conclusion == "failure"` from the spilled file.
