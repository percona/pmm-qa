# .claude/agents/investigator.md — recover discarded per-unit timing from surviving marker lines and CI line timestamps

- Added: 2026-09-14
- Applies to: .claude/agents/investigator.md
- Evidence: `pmm-framework --parallel` buffers each setup's output to a temp file and, on success, prints only `[i/n] <spec>: OK` before `rm -rf`-ing the log dir (`qa-integration/pmm_qa/pmm-framework/lib/execution.sh`), so the session twice called slow setups undiagnosable and proposed adding instrumentation. The `Starting [i/n] <spec>` and `[i/n] <spec>: OK` lines do survive in the job log, and diffing GitHub's own per-line timestamps gave exact per-spec wall-clock for every past run (main nightlies: no spec over 8m49).
- Proposed change: Add to the log-reading guidance that before concluding a duration cannot be measured or that instrumentation is needed, check whether the tool still emits start/end marker lines — the platform stamps every console line (GitHub Actions and Jenkins alike), so any surviving marker pair yields timing for historical runs. Note the two access traps: `gh api repos/<o>/<r>/actions/jobs/<id>/logs` needs `--allow-escape-sequences` or it refuses to print, and it returns 404 while the job's run is `in_progress` even if the step of interest already finished — time a live job from the jobs API step timestamps instead.
