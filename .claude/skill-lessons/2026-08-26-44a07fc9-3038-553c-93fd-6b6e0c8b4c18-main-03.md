# .claude/agents/investigator.md — re-run the failed FB job to confirm a flake verdict, not just to be helpful

- Added: 2026-08-26
- Evidence: After a repro VM showed the failing PSMDB image build succeeding twice, re-running only the failed job on the original FB Tests run (`rerun_failed_jobs`) brought the whole 48-check matrix to `success` on attempt 2. That confirmed the didn't-reproduce verdict in the real CI environment — same runner class, same inputs, no local-environment caveat — and cleared the developer's PR in the same step. The agent's flake branch says only "say so and stop", and its FB relay wording offers nothing beyond "PMM-QA is addressing it", even though the `fb-tests` skill already documents `rerun_failed_jobs` and FB Reporter uses it.
- Proposed change: In the didn't-reproduce / flake branch, after the reproduction comes back clean, re-run the failed job(s) on the original run and report the outcome in the pmm-submodules comment. Treat it as verification rather than courtesy: a green re-run is the strongest available evidence for the verdict, and a second failure means the verdict was wrong and the case reopens as a real failure instead of closing as a flake.
