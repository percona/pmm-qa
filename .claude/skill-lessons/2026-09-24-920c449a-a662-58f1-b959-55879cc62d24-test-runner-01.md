# .claude/skills/linode-ha-provisioning/SKILL.md — lighter fresh-install swap: keep CRDs, reuse release name `pmm-operators`, server-side apply PG/ClickHouse CRDs

- Added: 2026-09-24
- Applies to: target only (recurrence of the 2026-09-23 swap/fresh-install entries)
- Evidence: Replacing the relay's pmm-ha 1.6.1 / deps 1.0.0 with a fresh install of CI-built 1.8.0 / 1.2.0 (helm uninstall both, delete ns, no CRD deletion) failed twice. `helm install pmm-ha-operators` hit `invalid ownership metadata` on the kept VM CRDs (annotated `pmm-operators`), and pmm-ha then hit `spec.postgresVersion: 18 ... <= 17` from stale pg CRDs. Reusing release name `pmm-operators`, then `kubectl apply --server-side --force-conflicts -f <deps>/charts/{pg-operator,altinity-clickhouse-operator}/crds/` and restarting the pg-operator deployment, gave a clean install in ~10 min. No finalizer or CRD deletion was needed. HAProxy is ClusterIP afterwards, so a port-forward is needed.
- Proposed change: In the swap section's fresh-install recipe, install deps under the relay's release name `pmm-operators` and server-side apply the non-VM subchart CRDs before `helm install pmm-ha`. Present that as the default, with the full CRD/finalizer teardown kept as the fallback.
