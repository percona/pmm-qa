# .claude/skills/add-ha-test/SKILL.md — never take HA agent liveness from inventory alone; prove a new test by breaking the behaviour

- Added: 2026-09-22
- Applies to: target only
- Evidence: After `supervisorctl stop pmm-agent` on a standby HA pod its node metrics went stale, yet every pod's `/v1/management/nodes` kept reporting that agent connected and its exporters running (pmm-managed's HA-only disconnect write fails with `context canceled`); the new PMM-T2107 test's inventory checks passed in that broken state and only its metric-freshness check failed — first with a misleading "wrong exporter" message, because the stale series had dropped out of the instant query.
- Proposed change: State that agent liveness in an HA test must come from scrape freshness (`timestamp()` of the node's own series against `time()`), never inventory status alone, and that a new HA test is validated by breaking the behaviour on one pod (`kubectl exec <pod> -c pmm-ha -- supervisorctl stop|start pmm-agent`) and confirming it fails on the intended assertion, with a non-empty result asserted separately from label equality.
