# .claude/skills/jenkins-builds/SKILL.md — In an Ansible build, a `fatal:` line is usually not the failure

- Added: 2026-09-20
- Applies to: .claude/skills/jenkins-builds/SKILL.md
- Evidence: A package-testing build's cause was reported to the user as its first `fatal: [127.0.0.1]: FAILED` line; that attribution was wrong. The log held 91 `fatal:` lines of which 90 were followed by `...ignoring`, and the one un-ignored fatal was a different task entirely — the correct cause, which the branch author had already found.
- Proposed change: When triaging an Ansible-driven build, do not name a cause from the first `fatal:` line. Find the `fatal:` that is NOT followed by `...ignoring`, and cross-check the `PLAY RECAP` `failed=` and `ignored=` counts to confirm how many failures were real.
