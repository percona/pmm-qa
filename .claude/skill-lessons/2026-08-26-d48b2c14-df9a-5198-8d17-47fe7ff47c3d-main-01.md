# .claude/agents/investigator.md — never say "flaky" before the re-run; it is the first check, not the post-repro confirmation

- Added: 2026-08-26
- Evidence: A routine firing arrived with no run payload, so the agent swept CI itself and found one red FB check on a pmm-submodules PR (`@mongodb-exporter`, PMM-T1333 "MongoDB Collections Overview", `Expected 2 Elements without data but found 7`, run against pmm-qa `main`). Without re-running the failed job and without a VM reproduction, it reported to the user that the failure "looks intermittent" — resting only on the same test being green on two other runs that day — and handed the decision back ("say the word and I'll take it"). The user's correction was "Did you try rerunning the test if you just believe it's flaky?". `rerun_failed_jobs` on the original run then took one call and no VM. Nothing in the agent bound it to that: its flake branch sits after "Reproduce", so it reads as reachable only via a VM, and the `rerun_failed_jobs` recipe in `fb-tests` lives under "Green gate (FB Reporter)", scoped to the screenshot gate rather than to the investigator's verdict.
- Proposed change: In the FB branch of the Reproduce step, re-run the failed job(s) on the original run first — before provisioning a VM — as the cheapest evidence available and the only one gathered in the real CI environment. Pair it with a rule that "flaky", "intermittent", or "not your change" may not appear in any user, Slack, or PR-comment output until that re-run or a VM reproduction has actually been performed: circumstantial evidence (the same test green on another run or another PR) supports the hypothesis but never the verdict, and where the cheap check is available the agent takes it instead of returning the decision to the user.
