# .claude/agents/investigator.md — re-run an FB failure before calling it flaky; nightly cannot be re-run

- Added: 2026-08-26
- Evidence: A routine firing arrived with no run payload, so the agent swept CI itself and found one red FB check on a pmm-submodules PR (`@mongodb-exporter`, PMM-T1333 "MongoDB Collections Overview", `Expected 2 Elements without data but found 7`, run against pmm-qa `main`). Without re-running the failed job it told the user the failure "looks intermittent" — resting only on the same test being green on two other runs that day — and handed the decision back. The user's correction was "Did you try rerunning the test if you just believe it's flaky?"; `rerun_failed_jobs` on the original run then took one call and no VM. Nothing in the agent bound it to that: the `rerun_failed_jobs` recipe in `fb-tests` sits under "Green gate (FB Reporter)", scoped to the screenshot gate rather than to the investigator's verdict. The same user scoped the fix to the FB source only: `nightly-e2e-tests-matrix.yml` runs against an external PMM Server (its jobs carry a `Sanity check remote PMM Server reachability` step and a `PMM_UI_URL` pointing at a fixed address, not a server the job starts), and that server is gone by the time the failure is investigated, so a nightly job cannot be re-executed for evidence.
- Proposed change: In the FB branch, when an FB check has failed and the suspicion is flakiness, re-run the failed job(s) before treating flakiness as the answer. Note alongside it that nightly cannot be re-executed, as it depends on an already-dead external PMM Server.
