# .claude/skills/fb-tests/SKILL.md — a green test step hides real failures that the Launchable record step prints in full

- Added: 2026-09-15
- Applies to: .claude/skills/fb-tests/SKILL.md, .claude/agents/investigator.md
- Evidence: In the failed FB job the "Run UI tests … with launchable" step concluded `success` after 11 minutes while its own tail read `3 failed / 7 passed`; the step that actually went red was the later "Record launchable test results". That step's output carried the whole failure set — a `Files found / Tests found / Tests passed / Tests failed` table, then `Actionable Failure Details:` with one `##[group]` per failing test giving spec path, testcase name, parameterised data row and the assertion error. `grep -n '##\[group\]'` over the job log landed on them directly, without paging through the Playwright step.
- Proposed change: Record that the test step's `conclusion` is not the verdict for a Launchable-wrapped job, and that the failing spec paths, test names and assertion errors are read from the "Record launchable test results" step's `Actionable Failure Details:` groups — locatable with one `grep -n '##\[group\]'` over the job log.
