# .claude/agents/pr-maintainer.md — a PR wake event's head_sha can name a superseded commit

- Added: 2026-09-14
- Applies to: .claude/agents/pr-maintainer.md, and any session subscribed to PR activity
- Evidence: A `check_suite.completed` event on a pmm-qa PR named `head_sha` 5ff7959 while the PR's live head was fb91d05; reading it as "CI is green" would have missed the 36-job E2E suite that had only just started on the real head. CodeRabbit's summary comment, edited in place minutes later so its timestamp looked current, likewise still carried `change_assessment_commit:"5ff7959"` and a risk line describing a hole already fixed in fb91d05 and separately confirmed fixed by the bot in a review thread.
- Proposed change: Before treating any automated PR signal as current state, compare the SHA it names — `head_sha` on a check-suite event, `change_assessment_commit` or the `Merge Risk … up to <sha>` banner on a CodeRabbit summary — against the PR's live `head.sha` from `pull_request_read` `get`, and re-read the check runs when they differ; note that an edited-in-place bot summary carries a fresh timestamp over a stale assessment, so recency is not evidence of currency.
