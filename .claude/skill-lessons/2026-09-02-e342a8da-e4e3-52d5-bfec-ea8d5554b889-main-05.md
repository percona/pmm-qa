# .claude/skills/repos/SKILL.md — the Percona Jenkins MCP needs an explicit master argument

- Added: 2026-09-02
- Applies to: all agents reading Percona Jenkins builds
- Evidence: Two batched `mcp__Percona-Jenkins-MCP__*` calls for a `pmm.cd.percona.com` build both failed with "No Jenkins master selected. Pass the master argument, send the x-jenkins-master header, set the jenkins_master default, or configure exactly one master. Configured: ['ps80', 'psmdb', 'pxc', 'cloud', 'pmm', 'pxb', 'ps57', 'rel', 'pg']", and succeeded only when retried with `master: "pmm"`. The server's own tool docs describe the argument as optional ("omit for the default"), which is misleading here because no default is configured; this skill is the access/tool-map home and documents GitHub MCP access but says nothing about Jenkins MCP access.
- Proposed change: Add a short Jenkins-access note to the access section: PMM builds live on the `pmm` master, and every per-master `mcp__Percona-Jenkins-MCP__*` call must pass `master: "pmm"` explicitly despite the argument being documented as optional.
