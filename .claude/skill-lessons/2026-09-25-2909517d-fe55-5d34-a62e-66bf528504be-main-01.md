# .claude/skills/linode-docker-provisioning/SKILL.md — reproducing a Jenkins package test needs a Nomad-enabled server and a fresh VM per run

- Added: 2026-09-25
- Applies to: linode-docker-provisioning and investigator.md (reproducing `package_tests/pmm3-client_*.yml` failures)
- Evidence: Running `pmm3-client_integration.yml` (`ansible --connection=local`) against a plain `perconalab/pmm-server:3-dev-latest` on the VM failed twice at "nomad_agent never reached Running" (the CI staging server runs nomad-server with `pmm_public_address` set); after that was fixed, a second playbook run on the same box failed at PSMDB `rs.initiate()` "already initialized", so `sync.sh` before/after on one box could not work and a fresh VM was needed.
- Proposed change: Add a package-test recipe: start the server with `-e PMM_ENABLE_NOMAD=1 -e PMM_PUBLIC_ADDRESS=<vm-ip>:8443 -p 4647:4647`, export the job's `get_build_parameters` values (`PMM_SERVER_IP=127.0.0.1:8443`, `ADMIN_PASSWORD`, `install_repo`, `PMM_VERSION`, `METRICS_MODE`, `TARBALL_LINK`), and run the before (main) and after (fix) playbooks on separate fresh VMs, because these playbooks are not idempotent.
