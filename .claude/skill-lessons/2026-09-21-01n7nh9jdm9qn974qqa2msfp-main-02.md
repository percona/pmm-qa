# .claude/skills/linode-ha-provisioning/SKILL.md — swapping pmm-ha alone onto a 2.x pg-operator breaks pmmuser auth on the new pods

- Added: 2026-09-21
- Applies to: target only
- Evidence: Upgrading only the `pmm-ha` release to the PMM-HA-GA chart (1.8.0, pg-db 3.1.0) over the relay's `pmm-ha-dependencies` 1.0.0 was rejected with `spec.postgresVersion: Invalid value: 18: ... should be less than or equal to 17` after the StatefulSet had already rolled; the chart's pre-upgrade hook recreated `pmmuser-credentials` and the 2.x operator regenerated its password, so the new `3-dev-latest` pod looped on `cannot auto-provision database in HA mode: pq: password authentication failed for user "pmmuser"` while the old pods stayed Ready on pooled connections. Patching `pmm-secret` PG_PASSWORD to the operator's `pmmuser-credentials` password and deleting the stuck pod let the rollout finish.
- Proposed change: In the swap section, upgrade `pmm-operators` to the branch's `charts/pmm-ha-dependencies` before `pmm-ha` whenever the branch chart pins a newer pg-db major, and list the pmmuser auth loop with the secret-sync recovery as a fourth thing a green-looking swap hides.
