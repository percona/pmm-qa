# .claude/agents/investigator.md — derive a PR's "this affects X" list by grepping the triggering condition, not the feature

- Added: 2026-09-08
- Applies to: .claude/agents/investigator.md
- Evidence: A PR body named four workflows as the callers a signal-handler fix mattered for, listed because they pass `--parallel`; review showed none of them wraps the tool in `timeout`, so the handler fires there only on job cancellation, and the one caller that is both `timeout`-wrapped and multi-spec was missing from the list entirely. A grep for `timeout` among the `--parallel` callers produced the correct two-row set in one command.
- Proposed change: In the PR step, require any "this change affects <these callers/tests/jobs>" claim to be produced by grepping the condition that actually triggers the changed code path, and to state the complement (who is unaffected and why), rather than listing everything that uses the surrounding feature.
