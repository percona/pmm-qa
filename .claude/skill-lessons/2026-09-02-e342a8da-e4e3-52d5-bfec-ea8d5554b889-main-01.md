# .claude/skills/linode-docker-provisioning/SKILL.md — run.sh drops long commands; launch them detached and poll

- Added: 2026-09-02
- Applies to: target only
- Evidence: `run.sh <id> -- ./pmm-framework --database psmdb,SETUP_TYPE=sharding` failed three times with `curl: (52) Empty reply from server` / `failed to reach exec-server` after roughly 4-5 minutes, while the setup itself needs 20-40 and kept running on the box unaffected; a local poll loop written to wait it out was killed twice at exit code 143 because the Bash tool hard-caps at 600000ms regardless of its timeout argument. The skill documents polling only for the relay's provisioning call, not for `run.sh`.
- Proposed change: In the databases step, instruct that any remote command expected to outlast ~4 minutes be launched detached (`nohup ... >/tmp/<name>.log 2>&1 &`) and then polled with separate short `run.sh` calls using a remote `sleep` of 120-240s each, since one long call is dropped and a local foreground sleep is unavailable.
