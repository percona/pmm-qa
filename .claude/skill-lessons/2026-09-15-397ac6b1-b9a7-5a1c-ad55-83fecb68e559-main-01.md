# .claude/agents/investigator.md — a pmm-qa main regression makes sibling Investigators fire on different submodules PRs at once

- Added: 2026-09-15
- Applies to: .claude/agents/investigator.md
- Evidence: The FB failure's root cause was a regression merged to pmm-qa `main`, so every submodules PR whose feature build ran after that merge went red identically and woke its own Investigator session on a different PR number. The step-1 open-PR sweep came back clean at ~16:40 UTC; a sibling session triggered by a *different* submodules PR opened the fix PR at 16:46 and merged it at 17:13, while this session was still provisioning and running a control arm for the same cause. Step 1 currently frames the sibling hazard only as "the nightly dispatches nine runs minutes apart on the same head", which does not describe a cross-PR sibling, and both dedup checks are blind to a fix that has already merged.
- Proposed change: In step 1, state that a shared pmm-qa `main` regression turns every open submodules PR into an independent trigger, so siblings may carry different PR numbers; require the sweep to match on the failing test identifiers rather than the trigger PR, and to include pmm-qa PRs **merged** in the last few hours alongside open ones.
