# .claude/skills/linode-docker-provisioning/SKILL.md — Stacking background sleeps to wait on a detached run does not add up, and an immediate poll of a just-launched wait always reads empty

- Added: 2026-09-15
- Applies to: all skills that wait on detached remote work (also `.claude/agents/investigator.md`, House style in `CLAUDE.md`)
- Evidence: While waiting for a detached `pmm-framework` setup and a CI re-run, the agent launched successive background `sleep` waits (240s, 300s, 400s, 500s, 560s, 590s) and read each task's output file in the very next turn. The waits ran concurrently rather than sequentially, so ~50 minutes of issued sleep advanced the box's wall clock by ~8 minutes (`date -u` went 02:51 -> 02:59 -> 03:00), and every immediate read returned an empty file; roughly 20 turns produced no information.
- Proposed change: In the "Anything longer than ~10 minutes runs detached" section, after the sentinel-polling recipe, state the waiting form explicitly — issue exactly ONE wait, as a `run_in_background` Bash `until <sentinel>; do sleep N; done` loop (it exits and notifies once when the condition holds) or a `Monitor` armed on the terminal condition, then stop issuing commands until the notification arrives — and warn that concurrent background sleeps overlap instead of summing and that reading a wait's output file in the turn that launched it always returns empty.
