# .claude/agents/investigator.md — read a candidate control run's head_branch before its logs; a green run on a feature branch is a bisect, not a control

- Added: 2026-09-19
- Applies to: .claude/agents/investigator.md
- Evidence: A nightly failure on `main` was triaged against the eight `nightly-e2e-tests-matrix` runs from the previous evening, taken for the dispatcher's sibling batch. They were dispatches on a feature branch (`head_branch` in the same `list_workflow_runs` payload already read), so their green results were the branch's own fixes, not a healthy baseline. Six run-logs zips and a wrong server-build hypothesis were spent before `head_branch` was noticed; both runs' `logs/pmm-version.txt` then showed a byte-identical server FullCommit and build_time, leaving the pmm-qa ref as the only variable, and one `git diff origin/main <green head_sha> -- <failing spec paths>` named the fix commit for all three failing tests and the open PRs carrying them.
- Proposed change: In the nightly batch guidance, state that the batch's siblings are a control group only when their `head_branch`/`head_sha` match the failed run's, and that a green run on another ref is instead a ready-made bisect — diff `origin/main` against that run's head over the failing spec paths, before any product-diff or build archaeology, because it names the fix commit and the PR that already covers the failure.
