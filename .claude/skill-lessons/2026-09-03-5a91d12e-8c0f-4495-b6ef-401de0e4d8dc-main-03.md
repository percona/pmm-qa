# CLAUDE.md — never edit a tracked config to work around local tooling; patch a copy

- Added: 2026-09-03
- Applies to: all skills and agents
- Evidence: To get eslint past a plugin that crashes on this checkout's Node, the session ran `sed -i '' "s|import unicorn from 'eslint-plugin-unicorn';||" eslint.config.mjs` against the repo's tracked lint config, which then failed with `ReferenceError: unicorn is not defined` and had to be undone with `git checkout --`. Writing the patched config to a scratch path instead produced the same signal with the tracked file untouched.
- Proposed change: Add to the House style section: a local tooling workaround never mutates a tracked file - copy it to the scratch directory, patch the copy, and point the tool at it with its `--config`/`--project` flag.
