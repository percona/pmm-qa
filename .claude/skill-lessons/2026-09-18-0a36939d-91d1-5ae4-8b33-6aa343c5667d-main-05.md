# .claude/agents/investigator.md — An unregistered PMM entity stays selectable in dashboards and fakes a product gap

- Added: 2026-09-18
- Applies to: target only
- Evidence: Three "Expected 0 Elements without data" failures across two lanes resolved to one cause: a setup retry had `pmm-admin unregister`ed the first attempt's nodes, which removes them from inventory but leaves their ingested samples. Every PMM dashboard filter is `label_values(...)` against the TSDB, so the dead names stayed in the list, sorted first, and Grafana defaulted to one. Lanes with zero setup retries had none of these failures; 44 empty panels factored exactly as 22 panels x 2 duplicate services, one live and one dead.
- Proposed change: Add to the classification guidance — before calling a whole-dashboard "no data" a product or metric gap, check whether the selected entity is a retry leftover (inventory API vs the dashboard's `label_values` list disagree), and compare against a lane whose setup did not retry.
