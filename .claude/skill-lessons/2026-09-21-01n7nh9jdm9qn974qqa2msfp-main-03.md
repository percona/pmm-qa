# .claude/skills/linode-docker-provisioning/SKILL.md — the executablePath pin must be set per project, not at top-level use

- Added: 2026-09-21
- Applies to: target only
- Evidence: An untracked sibling config spreading the repo config and setting top-level `use.launchOptions.executablePath` still failed with `Executable doesn't exist at /opt/pw-browsers/chromium_headless_shell-1234/...`, because the repo's `chromium` project defines its own `launchOptions` (`args`), which replaces the top-level object; mapping `projects` and merging `executablePath` into each project's `launchOptions` made the suite run.
- Proposed change: In the scratch-config instruction, show the override applied inside each entry of `projects[].use.launchOptions` (spreading the project's existing launchOptions) rather than in top-level `use`.
