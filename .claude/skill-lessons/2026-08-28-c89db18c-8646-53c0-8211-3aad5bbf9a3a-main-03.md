# .claude/skills/linode-ha-provisioning/SKILL.md — adding a remote DB service on an HA cluster: pmm_agent_id is required, push mode is rejected, and metrics need a scrape interval

- Added: 2026-08-28
- Applies to: target only
- Evidence: Adding a remote MySQL via `POST /v1/management/services` failed with "invalid AddMySQLServiceParams.PmmAgentId: value length must be at least 1 runes" until a pmm-agent id from `/v1/inventory/agents` was passed; a query for `mysql_up` about a minute after a successful add returned no series, which prompted deleting and re-adding the service with `metrics_mode: METRICS_MODE_PUSH` — rejected with "push metrics mode is not allowed for exporters running on pmm-server". Pull mode was in fact correct: node_exporter series from the pmm-server nodes were already in VictoriaMetrics, and the re-added service's metrics and QAN rows appeared on their own after a couple of scrape intervals.
- Proposed change: Add a short "Add a remote database service" subsection to "Verify HA behaviour" stating that the mysql/postgresql payload needs an explicit `pmm_agent_id` (from `/v1/inventory/agents`, e.g. the leader's node agent), that `metrics_mode` must be left at its default because push mode is rejected for exporters on a pmm-server node, and that metric absence is only meaningful after polling the datasource proxy for a couple of scrape intervals.
