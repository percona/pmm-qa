# .claude/skills/verification-depth/SKILL.md — pmm-managed re-logs env-var warnings on every setup retry, so their count is timing-dependent

- Added: 2026-09-23
- Applies to: any check of PMM env-var warnings/errors in /srv/logs/pmm-managed.log (test-runner manual QA, CLI tests)
- Evidence: Booting one FB image 12 times, 2 boots logged the new env warning twice in pmm-managed.log (once in docker logs); both times "Retrying in 2s." after a VictoriaMetrics readiness failure sat between the copies, and the pre-existing "unknown environment variable" warning duplicated identically, so it was retry behaviour, not the duplicated-warning bug the ticket's How-to-test warned about.
- Proposed change: State that setup() in managed/cmd/pmm-managed/main.go reruns UpdateSettingsFromEnv on each retry, so pmm-managed.log may carry an env warning 1..N times: assert presence (not an exact count) there, count only pmm-managed-init's docker-logs line (once per start), and wait for "Setup completed." in pmm-managed.log before asserting a warning is absent.
