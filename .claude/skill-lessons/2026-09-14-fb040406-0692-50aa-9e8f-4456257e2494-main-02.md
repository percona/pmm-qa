# .claude/skills/qa-code-review/references/playwright-suite.md — a ported title keeps its literal suffix only while the byte-identity gate is still being spent

- Added: 2026-09-14
- Applies to: .claude/skills/qa-code-review/references/playwright-suite.md
- Evidence: The Tests table says a migrated DataTable title keeps its literal suffix, and that deriving the suffix from the row "is right for a native test and wrong for a ported one". A human reviewer rejected the verbatim suffix on a ported test — "Big test name that can't be rendered on artifacts" and "repeating of above informations" — and asked for `panelName` only (https://github.com/percona/pmm-qa/pull/1417#discussion_r4003741613). The merged title is `... @dashboards | ${panel.panelName}` at `e2e_tests/tests/dashboards/homeDashboards.test.ts:27`.
- Proposed change: Qualify that row — the literal suffix earns its place only until the migration's byte-identity gates have passed; once they have, the title carries the one value that varies, because a long title is unreadable in report artifacts. Interpolating a single field of the row is not the `JSON.stringify(row)` failure the rest of that row warns about.
