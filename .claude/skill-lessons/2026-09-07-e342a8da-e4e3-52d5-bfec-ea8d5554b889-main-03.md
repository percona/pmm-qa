# .claude/agents/investigator.md — a test step's duration is not when a test inside it ran

- Added: 2026-09-07
- Applies to: target only
- Evidence: A timing argument told a reviewer that the nightly's dashboard scenario "runs 45-60 min after setup", derived from the `Execute e2e tests` step lasting ~50 minutes. The user corrected it: that is the whole step's duration, setup finishes just before the step opens, and an individual scenario's position inside the step is unknown. The conclusion happened to survive, but only after being re-derived from measured failure timings instead.
- Proposed change: When reasoning about whether a timing-sensitive test could have observed a transient state, anchor the argument in measured state transitions (when the generator stopped, how long the metric window retains data) rather than in a step's start/end times; a step duration bounds when a scenario *could* have run, never when it did. Per-test timestamps come from the run's junit `result.xml` or its Launchable session, if the position actually matters.
