# .claude/skills/repos/SKILL.md — the listing MCP tools overflow the result cap, and their saved payloads are shaped inconsistently

- Added: 2026-08-26
- Evidence: In one investigation, four listing calls exceeded the tool-result token cap and were spilled to files instead of returned: `actions_list` (`list_workflow_jobs`, both pages of a 48-job run), `actions_list` (`list_workflow_runs`, 20 runs), and `list_pull_requests` (16 open PRs, already restricted with `fields`, but `body` is required for the dedup marker). Two `python3` attempts then failed with `TypeError: string indices must be integers` before the saved payload's shape was found, because the three methods nest differently: `list_workflow_jobs` saves `{"jobs": {"total_count": N, "jobs": [...]}}`, `list_workflow_runs` saves `{"total_count": N, "workflow_runs": [...]}`, and `list_pull_requests` saves a bare top-level list.
- Proposed change: In the "GitHub access — MCP-first" tool map, note that `actions_list` and `list_pull_requests` routinely exceed the result cap on these repos, that the overflow is expected rather than an error to retry with a smaller page, and that the saved file is parsed with `jq`/`python3` — recording the three shapes above so the first parse works.
