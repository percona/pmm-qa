# .claude/skills/linode-docker-provisioning/SKILL.md — the box's pmm-qa clone is shallow, so a pre-change revision cannot come from its own git history

- Added: 2026-09-21
- Applies to: .claude/skills/linode-docker-provisioning/SKILL.md, .claude/agents/investigator.md
- Evidence: Investigator's "run the pre-change revision on the same provisioned box" control ran `git -C /root/pmm-qa show HEAD~1:<path> > Dockerfile` on the VM; the relay's clone is shallow, so git exited `fatal: invalid object name 'HEAD~1'` while the redirect had already truncated the target to 0 bytes. Docker then reported `failed to solve: the Dockerfile cannot be empty`, which reads as a build fault rather than the git fault it was, and cost a full build cycle before the real cause was visible.
- Proposed change: State that the relay clones pmm-qa shallow, so a pre-change revision must be materialised in the session environment (`git show HEAD~1:<path>`) and shipped over as base64, or the box's clone deepened first; and never let a redirect whose producer can fail supply the next step's input — assert the file is non-empty before using it.
