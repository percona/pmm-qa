# .claude/agents/investigator.md — a nightly-only claim can be settled by running the Jenkins nightly against the fix branch

- Added: 2026-09-02
- Applies to: target only
- Evidence: The file states nightly cannot be re-run (its external PMM Server is gone) and to say in the PR "what only the next real CI/nightly run can confirm", so a setup-data fix shipped with a permanent open caveat about the tolerated-empty-panel total. A human then ran `pmm3-ui-tests-nightly-gha` #375, which came back SUCCESS with build parameter `PMM_QA_GIT_BRANCH=claude/jolly-curie-72zswc` and the same `DOCKER_VERSION` as the failing run -- i.e. the pipeline that dispatches the nightly workflow accepts an arbitrary pmm-qa branch, so the confirmation the caveat was waiting for was available on demand the whole time.
- Proposed change: Alongside the existing "nightly cannot be re-run" rule, note that the dispatching Jenkins job takes a `PMM_QA_GIT_BRANCH` parameter, so a fix branch can be confirmed in a real CI environment by running that job against it (or asking for it to be run) rather than leaving the caveat open; the distinction is that the *original failed run* cannot be re-executed, while a *fresh* nightly on the fix branch can.
