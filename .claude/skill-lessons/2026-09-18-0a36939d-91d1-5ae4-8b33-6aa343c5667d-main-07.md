# CLAUDE.md (House style) — `git add -A` cannot tell a conflict resolution from unrelated work in the tree

- Added: 2026-09-18
- Applies to: all agents and routines that commit in this repo
- Evidence: resolving a merge conflict on a PR branch, `git add -A` staged the two resolved files together with new bats tests written earlier in the same turn, producing one merge commit that mixed both and needed its message amended to cover them.
- Proposed change: while a merge or rebase is in progress, stage the resolved paths by name (`git add <path>…`, checked against `git diff --diff-filter=U --name-only`) and never `git add -A`.
