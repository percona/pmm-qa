# .claude/skills/linode-ha-provisioning/SKILL.md — an ERR trap alone leaks on CI cancel/timeout; provisioning needs signal traps + a workflow cancelled() cleanup + an out-of-band reaper

- Added: 2026-09-04
- Applies to: all skills that provision billing cloud resources from a script or CI job (refines the W36 provisioning-loop-hygiene entry, which said only "trap ERR")
- Evidence: A create loop guarded by `trap cleanup ERR` still leaked billing VMs when the CI job was cancelled or timed out — a human reviewer flagged it. A bash ERR trap fires only on a command's non-zero exit, not on the SIGTERM/SIGINT a CI cancel/timeout sends (same class as EXIT not firing on SIGTERM). Fix took two layers: trap TERM/INT/HUP in the script to run the teardown, and a workflow step gated `if: ${{ success() || cancelled() }}` so a job-level cancel also cleans up while a genuine test failure is kept for investigation. Neither survives a hard SIGKILL / a runner dying.
- Proposed change: For a script/CI job that creates billing resources, teardown-on-failure must cover three levels: trap ERR **and** TERM/INT/HUP in the script; add a CI cleanup step that runs on cancellation (`success() || cancelled()`), not only on success; and back both with an out-of-band tag-expiry reaper (an `expires-<epoch>` tag + scheduled sweep) as the only SIGKILL-proof guarantee. Never rely on an ERR/EXIT trap alone.
