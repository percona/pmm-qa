# .claude/agents/investigator.md — an identical number across retries rules out a timing race

- Added: 2026-09-18
- Applies to: all skills that diagnose flaky-looking test failures
- Evidence: a test reported "found 8" where it tolerated 5, the same 8 on every retry and on two separate runs; that was diagnosed as panels still loading and fixed with a wait, which changed nothing. The real cause was three panel types that can never render a no-data state, an exact and constant +3 that the identical count already implied.
- Proposed change: before attributing a count mismatch to timing, check whether the observed number is identical across retries; if it is, look for a structural cause of exactly that delta and say what would have varied had it been a race.
