# .claude/agents/investigator.md — fetch current review-thread ids before replying, never reuse one from earlier in the session

- Added: 2026-09-07
- Applies to: any agent replying to PR review threads
- Evidence: A new review round arrived days after the previous one. The reply to its first finding was addressed to a comment id remembered from the earlier round, so it landed on an unrelated thread that was already resolved and collapsed, and a second call was needed to fetch the current ids and post it on the right thread. The stray reply cannot be deleted, so the wrong thread now carries an off-topic comment.
- Proposed change: Before replying to or resolving any review thread, re-fetch the thread and comment ids for the current head (a `get_review_comments` call, paging to the newest cursor) and address replies only to ids from that response; ids seen earlier in a session go stale as soon as new commits or review rounds land.
