# .claude/agents/investigator.md — an FB failure can come from a feature branch that PREDATES a merged upstream change

- Added: 2026-09-21
- Applies to: target only
- Evidence: FB Tests on pmm-submodules PR #4475 failed PMM-T430 3/3 attempts. `percona/pmm` #5767 (merged 2026-09-18) trimmed trailing spaces from three GR dashboard panel titles and `percona/pmm-qa` #1449 trimmed the matching expectations the same day, but `ci.py` runs `git clone --depth 100 --single-branch --branch <branch>` per dep and never merges the dep's default branch, so the FB image still shipped `"Applied Transactions "`; `git merge-base --is-ancestor 3dd56df origin/PMM-14804-build-binaries-only` returned false. Neither pmm-qa nor PMM was defective.
- Proposed change: In step 3's FB branch, alongside the existing "expectation anticipates an open upstream PR → blocked fix" case, add its mirror: locate the upstream commit that changed what the test now expects and run `git merge-base --is-ancestor <commit> origin/<pmm feature branch>`; if absent the verdict is "stale feature branch" — open no pmm-qa PR (patching pmm-qa would revert a correct change and break it against `main`), and tell the developer to rebase and rebuild, noting a re-run cannot help because it reuses the same pinned image.
