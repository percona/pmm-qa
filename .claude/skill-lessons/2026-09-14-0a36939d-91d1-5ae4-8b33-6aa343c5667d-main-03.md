# .claude/agents/investigator.md — pin a package-repo publish race with the pool file's Last-Modified, and read apt's size mismatch in the right direction

- Added: 2026-09-14
- Applies to: .claude/agents/investigator.md
- Evidence: A failing setup step showed `File has unexpected size (180478134 != 180478192). Mirror sync in progress?` for a 180 MB `pmm-client` deb. apt prints `(actual != expected)`, so the *server* held the newer file and the client an older cached index — the opposite of the natural reading. A `curl -sI` on the pool URL returned `last-modified: Mon, 14 Sep 2026 10:13:19 GMT` against a step that began at `10:13:16`, and the live `Packages` index now carried the size and SHA256 the failure had rejected, which turned "probably a mirror problem" into a dated publish race the PR comment could stand on.
- Proposed change: In the external-fetch guidance, add that for an apt/yum size or hash mismatch the first number is what the server served and the second what the client's cached index expected, so a mismatch means the payload was republished under a stale index; confirm it by comparing the pool file's `Last-Modified` with the failing step's `started_at` and re-reading the live index for the rejected size/hash, and note that `Hit:` lines for that repo in the same log prove apt reused a cached index rather than refetching it.
