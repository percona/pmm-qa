# CLAUDE.md — "call the underlying tool" is read as "pick one linter", and the rest of the gate goes unrun

- Added: 2026-09-21
- Applies to: CLAUDE.md House style
- Evidence: The House style bullet "Never run a `.claude/hooks/` hook by hand as a check ... Call the underlying tool instead (`.claude/hooks/lint-changed.sh <files>`)" was read as "run the individual linter", so a workflow edit was validated with `actionlint` alone and pushed. CI's `Lint` job then failed on `yamllint --strict` (line-length 201 > 200) in the very file just edited — `lint-changed.sh` runs yamllint, actionlint, shellcheck, ruff, terraform fmt, hadolint, docker compose config and npm-groovy-lint, and fails the gate on any of them. One red CI cycle for a one-character overrun.
- Proposed change: Make the sanctioned invocation unambiguous — `lint-changed.sh <changed files>` IS the underlying tool and runs the whole gate; the thing never to run by hand is the harness hook wrapper. State that a single linter's pass is not the gate's pass.
