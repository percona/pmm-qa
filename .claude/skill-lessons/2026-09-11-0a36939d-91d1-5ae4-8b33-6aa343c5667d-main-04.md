# .claude/skills/repos/SKILL.md — gh cannot dispatch a workflow; the MCP run_workflow can

- Added: 2026-09-11
- Applies to: target only
- Evidence: Dispatching an A/B pair of `runner-e2e-tests-playwright.yml` runs, six `gh api -X POST .../workflows/<file>/dispatches` calls all failed with `403 Resource not accessible by integration`, while `mcp__github__actions_run_trigger` with `method: run_workflow` and the same inputs returned `204` and queued the runs. The session's `gh` token lacks `actions: write` even though `gh api` reads and `rerun_failed_jobs` both work, so the failure looks like a bad request rather than a scope gap.
- Proposed change: Add a "Dispatch a workflow" row to the tool map naming `actions_run_trigger` (`run_workflow`) as the only working path, and note that `gh api .../dispatches` 403s with "Resource not accessible by integration" because the session token has no `actions: write` — unlike the read calls and `rerun_failed_jobs` listed above it.
