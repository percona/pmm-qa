# .claude/agents/investigator.md — read a locator mismatch out of the trace's distinct attribute values before provisioning anything

- Added: 2026-09-21
- Applies to: target only
- Evidence: PMM-T430 on FB run 35571101067 timed out waiting for the `Applied Transactions` legend while the failure snapshot plainly showed that legend populated. `grep -o 'data-testid Panel header [A-Za-z0-9 %()/-]*' 0-trace.trace | sort | uniq -c` over the run's own artifact returned `37  …Applied Transactions ` against `2  …Applied Transactions`, naming the trailing-space mismatch in one command; `trace.network` separately showed the panel's own query returning data ~20 s before the wait began, which ruled out the product. A sibling session reached the same verdict on the same run only after provisioning a VM and building a locator probe.
- Proposed change: In step 2's trace guidance, add that when an assertion is self-contradictory (the awaited value is visibly present), the first move is to tally the **distinct values of the attribute the locator matches on** across `*-trace.trace` — near-identical rows with different counts expose whitespace and rename drift immediately — and to confirm from `trace.network` that the panel's query returned data before the wait started; both come from the failed run's existing artifact, so they precede any VM.
