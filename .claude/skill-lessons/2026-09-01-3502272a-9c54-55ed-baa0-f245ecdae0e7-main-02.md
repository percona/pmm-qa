# .claude/skills/fb-tests/SKILL.md — an FB re-run cannot pick up a fix merged after the build

- Added: 2026-09-01
- Applies to: target only
- Evidence: After the product fix for an FB failure merged upstream, the maintainer asked for "another round of tests"; re-running that PR's FB Tests would have reused `perconalab/pmm-server-fb:PR-<n>-<sha>`, built 25 minutes before the merge, and gone red again for the same reason. What actually confirmed the fix was dispatching pmm-qa `helm-tests.yml` against `perconalab/pmm-server:3-dev-latest` once Docker Hub showed that tag rebuilt after the merge (`hub.docker.com/v2/repositories/<repo>/tags/<tag>` → `last_updated`).
- Proposed change: In the flaky-triage/re-run section, state that a re-run only re-executes the same pinned FB image, so a fix merged after that build needs either a rebuilt feature build or a dispatch against a post-merge image — and check the image's `last_updated` before trusting it.
