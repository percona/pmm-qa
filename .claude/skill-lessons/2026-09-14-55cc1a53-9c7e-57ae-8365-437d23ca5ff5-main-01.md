# .claude/skills/linode-docker-provisioning/SKILL.md — pre-stage the MinIO images from quay.io before running pmm-framework

- Added: 2026-09-14
- Applies to: .claude/skills/linode-docker-provisioning/SKILL.md
- Evidence: `pmm-framework --database psmdb,SETUP_TYPE=pss` aborted at `start-rs-only.sh` with `pull access denied for minio/minio, repository does not exist or may require 'docker login'`; `docker pull minio/mc` failed identically while `docker pull quay.io/minio/minio:latest` succeeded on the same VM, so the Docker Hub names the psmdb-pbm compose file uses are simply gone. Pulling both from quay.io and `docker tag`-ing them to `minio/minio:latest` and `minio/mc:latest` before re-running let the unmodified framework finish (rs101/rs102/rs103 + minio up, 22/22 agents RUNNING). The whole psmdb leg had to be re-run to learn this.
- Proposed change: In step 3, before the `pmm-framework` invocation, add a one-line pre-stage for any run including `--database psmdb`: `docker pull quay.io/minio/minio:latest && docker tag quay.io/minio/minio:latest minio/minio:latest` (same for `minio/mc`), noting that MinIO no longer publishes to Docker Hub, that this is a local image tag and not a `qa-integration` edit, and that the real fix is repointing `qa-integration/pmm_psmdb-pbm_setup/docker-compose-rs.yaml` at quay.io.
