# .claude/skills/codeceptjs-migration/branch-workflow.md — committing a .sh file is blocked: Git Bash has no shellcheck

- Added: 2026-10-19
- Applies to: branch-workflow.md Commit messages, any commit that stages a shell file on this Windows machine
- Evidence: Row 39 framework fix staged `images/pxc-proxysql/setup.sh`. The pmm-qa plugin's `pre-commit-lint-gate.sh` ran `support_scripts/lint/lint-changed.sh` in Git Bash and blocked: `shellcheck not installed` (`ensure_shellcheck` only tries apt). WSL Ubuntu has shellcheck 0.9.0. A `~/bin/shellcheck` wrapper calling WSL was refused by the classifier as persistence. What worked: run the gate's exact command in WSL (`shellcheck -S warning <file>`, passed), then commit from the PowerShell tool, where lint-staged still runs.
- Proposed change: In Commit messages, say: before committing a `.sh` or `.bats` file from Git Bash, check `command -v shellcheck`; if missing, run `shellcheck -S warning <files>` in WSL and commit from PowerShell, naming that in the handoff. Better, ask Kiran to install shellcheck for Windows (`winget install koalaman.shellcheck`) so the gate runs itself.
