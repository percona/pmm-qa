# .claude/skills/codeceptjs-migration/orchestration.md — A post-run code fix can land past the gate cap with no run in between

- Added: 2026-10-06
- Applies to: orchestration.md Gates (five attempts per gate), run.md section 5 failure routing
- Evidence: On row 30 the initial gate passed on attempt 4, execution failed (T99 locator, T411 live-workload race), and the fixes took attempt 5. The T411 fix (a test-level `page.goto` straight after the beforeEach `goto`) was only judged through MCP, never executed, and failed with `net::ERR_ABORTED` on the next run. A further fix would need a sixth review, so the row stopped.
- Proposed change: Before a re-review spawned from an execution failure, have the runner execute just the changed tests (`--grep <ids>`) against the uncommitted fix; spend the gate attempt only on a fix that already ran green.
