# .claude/skills/codeceptjs-migration/orchestration.md — "local build" covers any compatible image, not only pmm-framework images

- Added: 2026-10-19
- Applies to: orchestration.md step 1 row selection and Local provisioning rule, for self-provisioned rows that `docker run` a stock image
- Evidence: Row 38 (externalPostgres_test.js) was skipped because its playbook runs `perconalab/percona-distribution-postgresql:17` (`postgres -c ...`, `POSTGRES_PASSWORD`), which was not in local Docker, and the only local build (pmm-framework `pmm-qa/pdpgsql`, systemd) does not take that interface. Kiran's rule is "local Docker or a local build, never a pull"; he pointed out a compatible image should have been built. The playbook already reads `POSTGRES_IMAGE`, so no test change was needed.
- Proposed change: In the Local provisioning rule, say: a database image missing from local Docker is built locally, from pmm-framework `images/` when its interface fits, else from a minimal Dockerfile that gives the interface the test uses, tagged `pmm-qa/<engine>-stock:<tag>`; a missing image is never a reason to skip a row.
